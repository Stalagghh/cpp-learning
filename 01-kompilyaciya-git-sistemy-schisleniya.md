# День 1 — Компиляция, git, системы счисления

> [!abstract] О чём эта лекция
> Три темы, которые к самому языку C++ отношения почти не имеют, но без них дальше нельзя. Что происходит между «я написал текст» и «программа запустилась». Как git запоминает состояния твоего кода. И почему компьютер считает двойками, а программисты пишут шестнадцатеричными.

## Часть 1. Первая программа построчно

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}
```

Четыре значащие строки, и в каждой есть что объяснить.

### `#include <iostream>`

Решётка в начале — признак **директивы препроцессора**. Препроцессор работает до компилятора и умеет только тупые текстовые операции. `#include` буквально означает «возьми содержимое этого файла и вставь сюда вместо этой строки».

`iostream` — заголовочный файл из стандартной библиотеки (io = input/output, stream = поток). Внутри — описания `cout`, `cin`, `endl`. Без него компилятор не знает слова `cout` и скажет `'cout' was not declared in this scope`.

Угловые скобки `<iostream>` — «ищи в системных папках». Кавычки `"myfile.h"` — «ищи рядом с моим файлом». Пригодится, когда начнёшь разбивать код на файлы.

### `int main()`

Точка входа. Когда операционная система запускает твою программу, она ищет функцию с именем `main` и начинает выполнение с её первой строки. Ровно одна `main` на программу — не больше и не меньше.

`int` перед именем — тип того, что функция вернёт наружу. Здесь: целое число.

### `std::cout << "Hello, World!" << std::endl;`

- `std` — **пространство имён** (namespace) стандартной библиотеки. Оно нужно, чтобы имена не сталкивались: если ты когда-нибудь напишешь свой `cout`, он не подерётся со стандартным. `::` — оператор доступа к содержимому пространства имён. Читается «cout из std».
- `cout` — объект «стандартный вывод», по умолчанию это твой терминал.
- `<<` — оператор вывода. Стрелочки показывают направление: данные текут **в** `cout`. Их можно ставить цепочкой, что и сделано: сначала в поток уходит текст, потом `endl`.
- `endl` — перевод строки (end line) плюс сброс буфера. Есть более дешёвый вариант `"\n"` — просто перевод строки без сброса; разницу почувствуешь позже, пока пиши `endl`.
- `;` — конец инструкции. Компилятору переносы строк безразличны, он ориентируется только на точки с запятой.

### `return 0;`

Функция `main` возвращает **код завершения** операционной системе. Договорённость такая:

- `0` — программа отработала успешно;
- любое другое число — что-то пошло не так.

Это не украшение. На этом стоит вся автоматизация в Linux: `g++ hello.cpp -o hello && ./hello` запустит `./hello` только если компиляция вернула 0. Оператор `&&` в терминале означает «выполняй следующее, только если предыдущее завершилось успешно».

Посмотреть код возврата последней команды в терминале:

```
echo $?
```

## Часть 2. Что делает `g++`: четыре этапа

Команда `g++ hello.cpp -o hello` выглядит как одно действие, но внутри четыре шага. Понимание этой цепочки — это половина умения читать ошибки.

```
hello.cpp
   │  1. препроцессор     (g++ -E)
   ▼
hello.i      ← чистый C++ без директив, с вклеенным iostream
   │  2. компилятор       (g++ -S)
   ▼
hello.s      ← ассемблер, текст, инструкции процессора
   │  3. ассемблер        (g++ -c)
   ▼
hello.o      ← объектный файл, машинный код, но ещё не программа
   │  4. компоновщик (linker)
   ▼
hello        ← исполняемый файл
```

### 1. Препроцессор

Обрабатывает всё, что начинается с `#`. Вклеивает содержимое `#include`, подставляет `#define`, вырезает ветки `#ifdef`. Комментарии тоже удаляются здесь. На выходе — обычный C++ без единой решётки, зато на несколько десятков тысяч строк длиннее (весь `iostream` теперь внутри).

### 2. Компиляция

Собственно перевод C++ в ассемблер. Здесь проверяется синтаксис и типы. **Почти все ошибки, которые ты видишь, рождаются на этом этапе:** пропущенная точка с запятой, необъявленная переменная, несовпадение типов.

### 3. Ассемблирование

Текст ассемблера превращается в машинные байты. Ошибок тут практически не бывает.

### 4. Компоновка (линковка)

Твой `hello.o` знает, что где-то существует функция вывода, но не знает, где именно она лежит. Компоновщик берёт все объектные файлы плюс стандартную библиотеку и сшивает их в единый исполняемый файл, проставляя реальные адреса.

> [!important] Как различать ошибки компиляции и компоновки
> **Ошибка компилятора** говорит про строку и файл: `hello.cpp:5:10: error: expected ';'`. Ищи опечатку в этой строке или чуть выше.
> **Ошибка компоновщика** выглядит иначе — `undefined reference to ...`, без номера строки. Значит синтаксис в порядке, но функция объявлена и нигде не реализована, или ты забыл подключить второй файл к сборке.
> Классика новичка: `undefined reference to 'main'` — ты назвал функцию `Main` или `mian`.

### Полезные флаги

```
g++ -Wall -Wextra hello.cpp -o hello
```

`-Wall -Wextra` включают предупреждения (warnings). Предупреждение — это не ошибка, программа соберётся, но компилятор говорит «выглядит подозрительно». Например, использование неинициализированной переменной. **Привыкай собирать с ними всегда** — они ловят половину багов до запуска.

```
g++ -g hello.cpp -o hello
```

`-g` кладёт внутрь отладочную информацию, без неё gdb покажет голый ассемблер вместо твоего кода.

> [!note] Ошибку читай сверху
> Компилятор от одной опечатки может выдать двадцать строк ругани. **Значение имеет только первая.** Остальные — последствия: он не понял одну строку и дальше запутался. Исправил первую → пересобрал → часто исчезли все.

## Часть 3. Git: три состояния файла

Главная путаница новичка в git — считать, что коммит сохраняет то, что лежит в папке. Это не так. Git различает **три места**, и файл движется между ними.

```
рабочая папка        индекс (staging)       репозиторий
(твои файлы)   ──►   (черновик коммита) ──►  (история)
                git add              git commit
```

### Рабочая папка

То, что ты реально видишь в файловом менеджере и правишь в редакторе. Git за этим наблюдает, но сам ничего не запоминает.

### Индекс — ключевое понятие

Индекс (он же staging area, «зона подготовки») — это **черновик следующего коммита**. Ты вручную кладёшь туда те изменения, которые хочешь зафиксировать.

Правильная метафора: коммит — это фотография, а индекс — кадр, который ты выстраиваешь до нажатия на спуск. Хочешь — попадут все файлы, хочешь — только два из пяти.

`git add файл` = «положить текущее состояние файла в кадр».

> [!warning] Самая частая ловушка
> `git add` фотографирует файл **в момент выполнения команды**. Если ты сделал `git add main.cpp`, потом ещё поправил `main.cpp` и сразу `git commit` — в коммит попадёт **старая** версия, та, что была на момент `add`. Правило: правишь после `add` → делай `add` заново.

### Репозиторий

Папка `.git` внутри проекта. Там лежит вся история — все коммиты навсегда. Коммит неизменяем, у него есть хеш (длинная строка вроде `a3f5b91...`), автор, дата и сообщение.

### Рабочий цикл

```
git status                       # что изменилось, что в индексе — смотри постоянно
git add day03/loop1.cpp          # положить конкретный файл в индекс
git add .                        # положить всё изменённое в текущей папке
git commit -m "day03: первый цикл for"
git push                         # отправить коммиты на GitHub
```

`git status` — самая полезная команда в git. Она не только показывает состояние, но и подсказывает следующую команду. Дёргай её после каждого шага, пока не привыкнешь.

### Про сообщения коммитов

Плохо: `фикс`, `ещё`, `asdfg`, `работает`.
Хорошо: `day03: цикл for, вывод чисел 1..N`, `day02: калькулятор со switch, обработка деления на 0`.

Сообщение пишется для тебя же через полгода. Формат «что сделано», а не «что я чувствовал».

### Локально и удалённо

`commit` сохраняет **на твоём компьютере**. GitHub про него ещё ничего не знает. Только `push` отправляет коммиты на сервер. Поэтому «коммит есть, а на GitHub пусто» — это не баг, ты просто не сделал `push`.

## Часть 4. Системы счисления

### Что вообще значит запись числа

Число `237` в десятичной системе — это сокращённая запись суммы:

$$237 = 2 \cdot 10^2 + 3 \cdot 10^1 + 7 \cdot 10^0$$

Позиция цифры задаёт степень основания. Единственное, что делает систему десятичной — основание 10. Оно не священно, у нас просто десять пальцев.

В двоичной системе основание 2 и всего две цифры, 0 и 1. `1011` означает:

$$1 \cdot 2^3 + 0 \cdot 2^2 + 1 \cdot 2^1 + 1 \cdot 2^0 = 8 + 0 + 2 + 1 = 11$$

Компьютер использует двойку не из любви к математике, а из физики: у транзистора надёжно различимы два состояния — есть напряжение и нет. Десять уровней различать пришлось бы с ошибками.

### Перевод из десятичной в двоичную: деление на 2

Алгоритм: делим число на 2 нацело, записываем остаток, повторяем с частным, пока не дойдём до нуля. Затем **читаем остатки снизу вверх**.

Переведём 13:

| делимое | ÷2 | остаток |
|---|---|---|
| 13 | 6 | **1** |
| 6 | 3 | **0** |
| 3 | 1 | **1** |
| 1 | 0 | **1** |

Снизу вверх: `1101`. Проверка: 8 + 4 + 0 + 1 = 13. ✓

**Почему это работает.** Остаток от деления на 2 — это в точности последний двоичный разряд (чётное число заканчивается на 0, нечётное на 1). Разделив нацело на 2, мы сдвигаем число на разряд вправо и выбрасываем эту цифру — как `n / 10` в десятичной отрезает последнюю цифру. Дальше повторяем с тем, что осталось. Читаем снизу вверх, потому что первым мы получили самый **младший** разряд, а записывается он последним.

> [!tip] Связь с Днём 3
> Это буквально та же пара операций, на которой стоят задачи про сумму цифр и переворот числа, только основание другое: `n % 2` и `n / 2` вместо `n % 10` и `n / 10`. Алгоритм перевода в двоичную = цикл `while (n > 0)`.

### Обратный перевод: сумма степеней

`10110` → расставляем степени двойки над разрядами справа налево:

| разряд | 1 | 0 | 1 | 1 | 0 |
|---|---|---|---|---|---|
| степень | 16 | 8 | 4 | 2 | 1 |

Складываем те, где стоит единица: 16 + 4 + 2 = **22**.

### Шестнадцатеричная система

Основание 16, цифр не хватает, поэтому после 9 идут буквы:

| hex | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| dec | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |

| hex | 8 | 9 | A | B | C | D | E | F |
|---|---|---|---|---|---|---|---|---|
| dec | 8 | 9 | 10 | 11 | 12 | 13 | 14 | 15 |

**Зачем она нужна.** 16 = 2⁴, поэтому одна шестнадцатеричная цифра — это ровно четыре двоичных разряда, всегда, без исключений. Значит перевод между hex и binary делается без всякой арифметики, по табличке:

```
1011 0110   →   B6
   B    6
```

Разбиваешь двоичное число на четвёрки справа налево, каждую заменяешь одной цифрой. Обратно — так же. Поэтому адреса памяти, цвета, коды ошибок, дампы пишут в hex: `0xB6` читается человеком, а `10110110` — нет.

Префиксы: `0x` — шестнадцатеричное (`0xFF`), `0b` — двоичное (`0b1011`), они же работают прямо в коде C++.

Полезные ориентиры для ИБАС: `0xFF` = 255 = максимум одного байта, `0xFFFF` = 65535, все четвёрки в hex «F» = все единицы в двоичном.

### Байт

8 бит = 1 байт. Восемь двоичных разрядов дают $2^8 = 256$ комбинаций: от `00000000` (0) до `11111111` (255). Отсюда 255 везде — от IP-адресов до RGB-цветов.

Тип `int` в C++ на твоей машине занимает 4 байта = 32 бита. Из-за этого его максимум — примерно 2 миллиарда, и об этом будет разговор в Дне 2.

## Часть 5. Долги — выучить наизусть

> [!important] Степени двойки
> Это не зубрёжка ради зубрёжки. Ты будешь видеть эти числа в размерах памяти, в границах типов, в сетевых масках, в лимитах — постоянно. Узнавать их с одного взгляда экономит часы.

| n | 2ⁿ | | n | 2ⁿ |
|---|---|---|---|---|
| 0 | 1 | | 6 | 64 |
| 1 | 2 | | 7 | 128 |
| 2 | 4 | | 8 | 256 |
| 3 | 8 | | 9 | 512 |
| 4 | 16 | | 10 | 1024 |
| 5 | 32 | | | |

Дальше — реперные точки:

| n | 2ⁿ | где встречается |
|---|---|---|
| 16 | 65 536 | максимум `unsigned short`, число портов TCP |
| 31 | 2 147 483 648 | граница знакового `int` |
| 32 | 4 294 967 296 | всё пространство IPv4 |

Максимум `int` — это $2^{31} - 1 = 2\,147\,483\,647$. Минус один, потому что один бит уходит на знак, а ноль тоже занимает место в диапазоне.

### Переводы для отработки на бумаге

Сделай сам, потом сверься. Метод — деление на 2 столбиком.

- 12 → ?
- 100 → ?
- 255 → ?

<details>
<summary>Ответы (открывать после попытки)</summary>

- 12 = `1100` (8 + 4)
- 100 = `1100100` (64 + 32 + 4)
- 255 = `11111111` (все восемь бит, максимум байта)

В hex: 12 = `0xC`, 100 = `0x64`, 255 = `0xFF`.
</details>

## Итог одной страницей

- `#include` вклеивает файл, `main` — точка входа, `return 0` — сигнал «всё хорошо» операционной системе.
- Путь кода: препроцессор → компилятор → ассемблер → компоновщик. Ошибки с номером строки — от компилятора, `undefined reference` — от компоновщика.
- Собирай с `-Wall -Wextra`. Читай первую строку ошибки.
- Git: рабочая папка → `add` → индекс → `commit` → репозиторий → `push` → GitHub. Индекс — черновик коммита, а не автосохранение.
- Перевод в двоичную: делить на 2, остатки читать снизу вверх. Работает потому, что остаток = младший разряд.
- Hex нужен, потому что одна его цифра = ровно четыре бита.
- Степени двойки до 2¹⁰ плюс 2¹⁶, 2³¹, 2³² — знать наизусть.
