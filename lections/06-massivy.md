# День 6 — Массивы

> [!abstract] О чём эта лекция
> Массив — много значений под одним именем, с обращением по номеру. Отсюда две большие вещи. Первая: данные теперь **остаются** в памяти, и по ним можно пройти дважды — именно это делает возможными сортировку, разворот и всё, что раньше было недоступно. Вторая: индексация с нуля и выход за границы. Здесь C++ впервые перестаёт тебя защищать, и это ровно тот механизм, который на твоей специальности называется переполнением буфера.

---

## 1. Зачем нужен массив

Задача: прочитать 5 чисел и вывести их в обратном порядке. Без массива:

```cpp
int a, b, c, d, e;
std::cin >> a >> b >> c >> d >> e;
std::cout << e << " " << d << " " << c << " " << b << " " << a;
```

Работает. А теперь 100 чисел. Или `n` чисел, где `n` вводит пользователь — сколько переменных объявлять, ты не знаешь.

Проблема глубже, чем «много писать». Переменные `a`, `b`, `c` — **разные имена**, а цикл умеет менять только значения, а не имена. Написать `for` по переменным `a…e` невозможно в принципе.

Массив решает это: имя одно, значений много, а обращаются к ним по **номеру** — числу, которое можно вычислить, увеличить, подставить из счётчика цикла.

```cpp
int a[5];
std::cin >> a[0] >> a[1] >> a[2] >> a[3] >> a[4];
```

А раз номер — это обычное число, то:

```cpp
for (int i = 0; i < 5; i++) std::cin >> a[i];
```

**Главная мысль дня:** массив соединяет цикл с данными. До сегодня цикл повторял действия, но помнить умел только одно значение в накопителе. Теперь он ходит по хранилищу.

## 2. Объявление и что происходит в памяти

```cpp
int a[5];
```

Это просьба выделить **пять подряд идущих** `int`, то есть 20 байт непрерывным куском. Не пять отдельных переменных где попало, а один блок:

```
        ┌────┬────┬────┬────┬────┐
   a:   │ 10 │ 20 │ 30 │ 40 │ 50 │
        └────┴────┴────┴────┴────┘
индекс:    0    1    2    3    4
адрес:  1000 1004 1008 1012 1016
```

Непрерывность — не деталь реализации, а причина, по которой обращение по индексу быстрое: адрес элемента считается арифметикой, а не поиском.

### Размер должен быть известен компилятору

```cpp
int a[5];              // хорошо
const int MAX = 100;
int b[MAX];            // хорошо

int n;
std::cin >> n;
int c[n];              // так НЕ пишут
```

Последняя строка на `g++` скомпилируется — это его расширение, а не стандарт C++. Она пройдёт у тебя и упадёт у другого компилятора, а на `-Wpedantic` выдаст предупреждение. Правильный приём на всю первую неделю:

```cpp
const int MAX = 100;    // сколько максимум может быть
int a[MAX];             // физический размер, задан навсегда
int n;                  // логический размер — сколько реально занято
std::cin >> n;
```

> [!important] Физический размер и логический размер
> Массив объявлен на 100 элементов, а работаешь ты с первыми `n`. Это две разные величины, и путать их нельзя: физический задан при объявлении и не меняется никогда, логический ты держишь в отдельной переменной `n` и меняешь сам. Массивы **не умеют** расти и уменьшаться. Когда в задаче 15 ты удаляешь элемент — ты не уменьшаешь массив, а уменьшаешь `n`.

### Инициализация

```cpp
int a[5] = {1, 2, 3, 4, 5};   // все пять заданы
int b[5] = {1, 2};            // b[2], b[3], b[4] станут нулями
int c[5] = {};                // все нули
int d[] = {1, 2, 3};          // размер вычислен компилятором: 3
int e[5];                     // МУСОР во всех пяти
```

Последняя строка — та же неинициализированная переменная из Дня 2, только теперь их пять. Массив на 100 элементов из мусора — источник самых непонятных ошибок: работает, пока читаешь только заполненную часть, и сходит с ума, как только вылезешь чуть дальше.

### Узнать размер

```cpp
std::cout << sizeof(a);                  // 20 — байт всего
std::cout << sizeof(a) / sizeof(a[0]);   // 5 — элементов
```

Приём рабочий, но у него есть неприятное свойство: он ломается, когда массив передаётся в функцию (там от него остаётся только адрес). Это тема второй недели; пока просто держи `n` в отдельной переменной и не полагайся на `sizeof`.

## 3. Индексация с нуля — почему именно так

Первый элемент — `a[0]`, последний — `a[размер - 1]`. Для `int a[5]` допустимы индексы 0, 1, 2, 3, 4. Индекса 5 не существует.

Это не прихоть авторов языка. **Индекс — это смещение от начала массива, выраженное в элементах.**

| Обращение | Смещение в элементах | Смещение в байтах | Адрес (если начало 1000) |
|---|---|---|---|
| `a[0]` | 0 | 0 | 1000 |
| `a[1]` | 1 | 4 | 1004 |
| `a[2]` | 2 | 8 | 1008 |
| `a[4]` | 4 | 16 | 1016 |

Формула: `адрес = начало + i * sizeof(тип)`. У первого элемента смещение ноль — он и есть начало. Считать с единицы означало бы вычитать единицу при каждом обращении.

> [!note] Куда это ведёт
> Из этой формулы позже вырастут указатели и вся арифметика адресов (уровень 3 карты), и она же лежит в основе чтения дампов памяти и разбора бинарей — то, чем ты будешь заниматься по специальности. Запись `a[i]` — это на самом деле сокращение от «взять то, что лежит по адресу `a + i`».

> [!warning] Ошибка «на единицу»
> Пять элементов, индексы 0…4, последний индекс на единицу меньше размера. Из-за этого:
> ```cpp
> for (int i = 0; i <= n; i++)     // ← ЛИШНИЙ проход, i == n за границей
> for (int i = 1; i <= n; i++)     // ← пропущен a[0], зато залез в a[n]
> ```
> Единственно верная форма обхода на всю жизнь: `for (int i = 0; i < n; i++)`. Строго `<`. Вспомни Дня 3: условие проверяется на один раз больше, чем работает тело, и последняя проверка — та, что цикл останавливает. Здесь она же спасает от выхода за границу.

## 4. Обход: заполнить и вывести

```cpp
#include <iostream>

int main() {
    const int MAX = 100;
    int a[MAX];
    int n;
    std::cin >> n;

    for (int i = 0; i < n; i++) {       // заполнили
        std::cin >> a[i];
    }

    for (int i = 0; i < n; i++) {       // вывели
        std::cout << a[i] << " ";
    }
    std::cout << '\n';
    return 0;
}
```

Два отдельных цикла, а не один — потому что сначала надо получить все данные, и только потом что-то с ними делать.

Все накопители из Дня 3 работают здесь без изменений, меняется только источник значения: вместо `std::cin >> x` теперь `a[i]`.

```cpp
long long sum = 0;
for (int i = 0; i < n; i++) sum += a[i];
double avg = (double)sum / n;      // приведение из Дня 2, иначе целочисленное деление
```

> [!warning] Три вещи, которых массив не умеет
> ```cpp
> std::cout << a;      // напечатает АДРЕС, а не элементы
> a = b;               // не скомпилируется: массив нельзя присвоить
> if (a == b)          // скомпилируется и сравнит АДРЕСА — всегда не то, что ты хотел
> ```
> Вывести, скопировать и сравнить массивы можно только поэлементно, циклом. Первая строка особенно коварна: она компилируется, печатает что-то похожее на число, и человек полчаса думает, почему «массив выводится неправильно».

### Заполнение случайными числами (задача 2)

```cpp
#include <random>

std::mt19937 gen(std::random_device{}());
std::uniform_int_distribution<int> dist(1, 100);

for (int i = 0; i < n; i++) {
    a[i] = dist(gen);
}
```

`gen` создаётся **один раз до цикла** — то же правило, что в Дне 4 про `srand` внутри цикла. Генератор внутри цикла даст тебе массив из одинаковых чисел.

## 5. Что изменилось принципиально: два прохода

В Дне 3 сумму `n` чисел можно было считать на лету, ничего не запоминая. А вот такую задачу — нельзя: **сколько элементов больше среднего?**

Чтобы сравнить элемент со средним, надо знать среднее. Чтобы знать среднее, надо прочитать все элементы. Значит нужно пройти по данным дважды, а для этого их надо где-то держать.

```cpp
long long sum = 0;
for (int i = 0; i < n; i++) sum += a[i];      // первый проход: считаем среднее
double avg = (double)sum / n;

int count = 0;
for (int i = 0; i < n; i++)                   // второй проход: сравниваем
    if (a[i] > avg) count++;
```

Вот это и есть смысл массива, а не «удобно хранить». Данные лежат, и к ним можно вернуться. Отсюда становятся возможны разворот, сортировка, сдвиги, сравнение элемента с соседом — весь сегодняшний список задач.

## 6. Выход за границы — главная тема дня

```cpp
int a[5] = {1, 2, 3, 4, 5};
std::cout << a[5];      // элемента с индексом 5 НЕ существует
a[10] = 42;             // запись в чужую память
a[-1] = 7;              // и это тоже
```

Что произойдёт: **компилятор промолчит, и программа, скорее всего, не упадёт.** Она прочитает или запишет байты, которые лежат рядом с массивом и принадлежат чему-то другому — другой переменной, служебным данным, чему угодно.

Это **неопределённое поведение**. Не «ошибка», а отсутствие каких-либо гарантий: сегодня работает, завтра портит соседнюю переменную, послезавтра падает, и всё это — один и тот же код.

### Почему C++ не проверяет

Проверка индекса — это сравнение перед **каждым** обращением к элементу. В цикле на миллион итераций это миллион лишних сравнений. C++ проектировался так, что за безопасность, которую ты не просил, ты не платишь. Расплата — ответственность за границы лежит целиком на тебе.

> [!important] Это прямо про твою специальность
> Запись за границу буфера — не абстрактная «ошибка новичка», а класс уязвимостей под названием переполнение буфера, на котором стоит внушительная часть истории эксплойтов. Механизм ровно тот, что выше: программа пишет данные туда, где кончился её массив, и затирает то, что лежит следом. Ты сейчас смотришь на него со стороны разработчика; по специальности будешь смотреть с другой стороны. Полезно, что первое знакомство происходит на своём коде из пятнадцати строк, а не на чужом бинаре.

### Как поймать: санитайзер

Компилятор не найдёт, а вот это найдёт:

```
g++ -std=c++17 -Wall -Wextra -g -fsanitize=address,undefined 01.cpp -o 01
./01
```

Программа с санитайзером при выходе за границу не «как-нибудь продолжит», а немедленно остановится и напечатает, что случилось, где именно и в какой строке. Тот же флаг стоит в разделе про сборку в твоём файле проектов — там он обязателен для проекта со своими структурами данных.

> [!tip] Привычка на весь день
> Все пятнадцать задач сегодня собирай с `-fsanitize=address,undefined`. Скорость на таких размерах данных не важна вообще, а найденная за секунду ошибка «на единицу» экономит полчаса догадок. Ошибка, которая «просто работает», — самая дорогая из всех.

Позже, когда дойдёшь до `std::vector`, у него окажется метод `at()`, который проверяет индекс и бросает исключение вместо тихой порчи памяти. Пока такой роскоши нет.

## 7. Скелеты дня

### Максимум и его индекс (задачи 4, 5)

```cpp
int maxVal = a[0];      // НЕ 0 — первым элементом!
int maxIdx = 0;
for (int i = 1; i < n; i++) {      // с единицы: нулевой уже взят
    if (a[i] > maxVal) {
        maxVal = a[i];
        maxIdx = i;
    }
}
```

Инициализация нулём — та самая ошибка из Дня 5, которая даёт «неверный ответ на тесте №7»: если все элементы отрицательные, ответом станет ноль, которого во входе не было. Начинай с `a[0]`, и такого случая просто не существует.

Заметь, что индекс обновляется **вместе** со значением, в том же блоке. Обновишь порознь — получишь максимум от одного элемента и индекс от другого.

### Линейный поиск (задача 8)

```cpp
int found = -1;                     // -1 значит «не найдено»
for (int i = 0; i < n; i++) {
    if (a[i] == x) { found = i; break; }   // нашли — дальше искать нечего
}
```

`-1` как признак отсутствия — общепринятая договорённость: это заведомо невозможный индекс. `break` из Дня 4 здесь по делу.

### `std::swap` — обмен двух значений

```cpp
std::swap(a[i], a[j]);
```

Руками это три строки через временную переменную:

```cpp
int tmp = a[i];
a[i] = a[j];
a[j] = tmp;
```

Напиши руками хотя бы раз и пойми, почему без `tmp` не выйдет: `a[i] = a[j];` затирает первое значение, и восстановить его уже нечем. Дальше пользуйся `std::swap` — он живёт в `<utility>`, но обычно подтягивается сам.

### Разворот на месте (задача 6)

Идея: обменять первый с последним, второй с предпоследним, и так до середины.

```cpp
for (int i = 0; i < n / 2; i++) {
    std::swap(a[i], a[n - 1 - i]);
}
```

Два места, где ошибаются:

- **`n / 2`, а не `n`.** Дойдя до середины, массив уже развёрнут. Продолжив, ты развернёшь его обратно и получишь исходный — и это самая обидная отладка, потому что кажется, что «код вообще ничего не делает».
- **`n / 2` для нечётного `n`.** Для `n = 5` целочисленное деление даёт 2, и середина `a[2]` остаётся на месте — именно так и надо. Целочисленное деление из Дня 2 здесь работает на тебя.

| `i` | обмен | массив `{1,2,3,4,5}` |
|---|---|---|
| 0 | `a[0]` ↔ `a[4]` | 5 2 3 4 1 |
| 1 | `a[1]` ↔ `a[3]` | 5 4 3 2 1 |
| 2 | `2 < 5/2` ложно | выход |

### Удаление по индексу со сдвигом (задача 15)

Дырку в середине массива оставить нельзя — все следующие элементы сдвигаются на одну позицию влево, а логический размер уменьшается:

```cpp
for (int i = pos; i < n - 1; i++) {
    a[i] = a[i + 1];
}
n--;                    // вот это и есть удаление
```

Граница `n - 1`, потому что внутри тела ты трогаешь `a[i + 1]`: при `i == n - 1` это было бы `a[n]` — выход за границу. **Каждый раз, когда в теле цикла стоит `i + 1`, граница уменьшается на единицу.**

Без `n--` элемент никуда не денется: последнее значение просто продублируется в хвосте. Физический размер массива при этом, разумеется, не меняется — меняется твоё представление о том, докуда он занят.

### Циклический сдвиг (задача 10)

Код не даю, дам ловушку: элемент, который вытесняется, надо **сохранить до** начала сдвига, иначе он будет затёрт и потерян навсегда. И подумай, в какую сторону идти циклом — с начала или с конца. Один из двух вариантов затирает данные на первом же шаге. Возьми массив из четырёх чисел и проверь на бумаге оба, прежде чем писать код.

## 8. Сортировка пузырьком — зачёт дня

Твой первый настоящий алгоритм. Разбирать не буду, дам идею и инструменты.

**Идея:** проходим по массиву и сравниваем каждую пару соседей. Стоят не в том порядке — меняем местами. За один такой проход самый большой элемент неизбежно доезжает до конца: как только он встретился, он побеждает во всех сравнениях подряд и едет вправо до упора.

Трассировка одного прохода по `{5, 3, 4, 1}`:

| сравниваем | пара | меняем? | массив после |
|---|---|---|---|
| `a[0]`, `a[1]` | 5, 3 | да | 3 5 4 1 |
| `a[1]`, `a[2]` | 5, 4 | да | 3 4 5 1 |
| `a[2]`, `a[3]` | 5, 1 | да | 3 4 5 → **1 в конце**: 3 4 1 5 |

Пятёрка на месте. Массив ещё не отсортирован, но хвост уже правильный — и следующему проходу его трогать не нужно.

Отсюда вопросы, на которые тебе нужно ответить самому, они и есть задача:

1. Сколько всего нужно проходов, чтобы гарантированно отсортировать `n` элементов? Почему `n - 1`, а не `n`?
2. До какой границы должен идти внутренний цикл на проходе номер `i`? Хвост из уже расставленных элементов проверять бессмысленно — как эта мысль выражается в условии цикла?
3. Почему внутренний цикл сравнивает `a[j]` и `a[j + 1]`, а не `a[j]` и `a[j - 1]`, и как от этого меняется граница?

> [!tip] Как отлаживать сортировку
> После каждого прохода внешнего цикла печатай весь массив целиком:
> ```cpp
> for (int k = 0; k < n; k++) std::cout << a[k] << " ";
> std::cout << '\n';
> ```
> И запускай на четырёх-пяти числах, не больше. Ты увидишь, как «всплывают» элементы, и сразу поймёшь, если проходов не хватает или граница внутреннего цикла не та. На массиве из двадцати чисел в этом выводе не разобраться.

### Сколько это стоит

Два вложенных цикла по `n` — значит порядка $n^2/2$ сравнений. Для 10 элементов около 50, для 1000 — около полумиллиона, для 100 000 — пять миллиардов, и это уже не работает.

Это тот самый эффект из Дня 4: вложенный цикл **умножает** работу, а не прибавляет. Позже это назовут $O(n^2)$ и покажут сортировки за $n \log n$; пузырёк пишут не потому, что он хорош, а потому, что на нём видно, как алгоритм устроен изнутри.

> [!note] Оптимизация, которую стоит добавить после того, как заработает
> Завести флаг: был ли хотя бы один обмен за проход. Не было ни одного — массив уже отсортирован, и остальные проходы можно не делать. На почти упорядоченных данных это огромная разница, а сам приём — флаг плюс `break` — ровно из Дня 4.

## 9. Типичные ошибки

| Код / ситуация | Что происходит | Симптом |
|---|---|---|
| `for (i = 0; i <= n; i++)` | лишний проход, обращение к `a[n]` | мусор в выводе или падение «в случайном месте» |
| `for (i = 1; i <= n; i++)` | пропущен `a[0]`, залез в `a[n]` | ответ стабильно неверный на первом элементе |
| `int a[n]` с переменным `n` | нестандартное расширение gcc | у тебя работает, у судьи или в другом компиляторе нет |
| `maxVal = 0` вместо `a[0]` | ноль оказывается ответом | WA, когда все числа отрицательные |
| разворот циклом до `n`, а не `n / 2` | массив разворачивается дважды | «код ничего не делает» |
| `a[i] = a[i + 1]` с границей `n` | обращение к `a[n]` | UB, иногда мусор в хвосте |
| удаление без `n--` | элемент остался, хвост продублирован | размер не изменился |
| `std::cout << a;` | печатает адрес | «странное число вместо массива» |
| `if (a == b)` | сравнение адресов | условие всегда одно и то же |
| генератор случайных чисел внутри цикла | одно и то же число | массив из одинаковых элементов |
| чтение неинициализированного массива | мусор из памяти | разные ответы при разных запусках |
| индекс из ввода без проверки | пользователь введёт 500 при `MAX = 100` | тихая порча памяти |

> [!warning] Проверяй индекс, пришедший извне
> Если индекс вводит пользователь (задача 15) — проверь его **до** обращения:
> ```cpp
> if (pos < 0 || pos >= n) { std::cout << "неверный индекс\n"; }
> ```
> Индекс из внешнего мира без проверки границ — это, в двух словах, содержание половины отчётов об уязвимостях. Заведи привычку сейчас, на пятнадцати строках.

## 12. Итог одной страницей

- Массив — непрерывный блок значений одного типа под одним именем, доступ по индексу-номеру. Он соединяет цикл с данными.
- Размер при объявлении — константа. Рабочий приём: `const int MAX`, физический размер, плюс отдельная переменная `n` для логического.
- Массивы не растут и не уменьшаются. «Удалить элемент» = сдвинуть хвост и уменьшить `n`.
- Индексы от 0 до `размер - 1`. Индекс — это смещение от начала в элементах, отсюда и ноль.
- Единственная верная форма обхода: `for (int i = 0; i < n; i++)`. Если в теле есть `a[i + 1]`, граница `n - 1`.
- Выход за границу — неопределённое поведение: компилятор молчит, программа обычно не падает, память тихо портится. Это механизм переполнения буфера.
- Ловится флагом `-fsanitize=address,undefined`. Сегодня собирай с ним всё.
- Индекс, пришедший от пользователя, проверяй до обращения. Всегда.
- Максимум инициализируется `a[0]`, никогда нулём.
- Разворот — до `n / 2`, обменом `a[i]` и `a[n - 1 - i]`.
- Массив нельзя вывести одной командой, присвоить или сравнить через `==` — только поэлементно.
- Смысл массива не в хранении, а в возможности пройти по данным дважды. Всё, что требует второго прохода, до сегодня было невозможно.
- Пузырёк: сравнение соседей, за проход самый большой уезжает в конец, хвост дальше не трогаем. Стоимость $n^2$ — вложенный цикл умножает работу.
