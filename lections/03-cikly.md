# День 3 — Циклы

> [!abstract] О чём эта лекция
> Цикл — это способ сказать компьютеру «повтори это» вместо того, чтобы писать одно и то же руками. Три конструкции: `while`, `for`, `do-while`. Все три делают одно и то же, различаются только удобством записи.

---

## 1. Зачем цикл вообще нужен

Задача: вывести числа от 1 до 5. Без цикла:

```cpp
#include <iostream>
int main() {
    std::cout << 1 << std::endl;
    std::cout << 2 << std::endl;
    std::cout << 3 << std::endl;
    std::cout << 4 << std::endl;
    std::cout << 5 << std::endl;
    return 0;
}
```

Работает. А теперь до 1000. Или до `N`, которое пользователь введёт с клавиатуры — ты вообще не знаешь заранее, сколько строк писать. Вот здесь копипаста ломается, и появляется цикл.

**Главная мысль:** в цикле код написан один раз, а выполняется много раз. Строка в файле одна — проходов по ней много. Это то, что новичку труднее всего уложить в голове: одна строка ≠ одно выполнение.

---

## 2. Три вопроса любого цикла

Любой цикл, в любом языке, отвечает на три вопроса:

1. **С чего начинаем?** (какое-то начальное состояние)
2. **Пока что продолжаем?** (условие — когда остановиться)
3. **Что меняется на каждом шаге?** (иначе цикл никогда не закончится)

Если хотя бы один вопрос без ответа — получается либо бесконечный цикл, либо цикл, который не выполнится ни разу. Дальше просто три разных способа записать эти же три вещи.

---

## 3. `while` — самый честный цикл

Начинаем с него, потому что в нём всё видно.

```cpp
#include <iostream>

int main() {
    int i = 1;              // 1. с чего начинаем
    while (i <= 5) {        // 2. пока это верно — повторяем
        std::cout << i << std::endl;
        i = i + 1;          // 3. что меняется
    }
    return 0;
}
```

Читается по-человечески: «пока `i` меньше или равно 5 — печатай `i` и увеличивай `i` на единицу».

### Как это выполняется по шагам

Компьютер не «видит цикл целиком». Он делает вот такую последовательность:

1. Создать `i`, положить туда 1.
2. Проверить `i <= 5`. Если **ложь** — прыгнуть за закрывающую `}` и забыть про цикл.
3. Если **истина** — выполнить тело (всё, что в фигурных скобках).
4. Дойдя до конца тела — вернуться к пункту 2.

### Таблица трассировки

Это главный инструмент отладки на бумаге. Расписываешь по шагам, что лежит в переменной:

| проверка | `i` | `i <= 5` | что напечатано | `i` после тела |
|---|---|---|---|---|
| 1-я | 1 | истина | 1 | 2 |
| 2-я | 2 | истина | 2 | 3 |
| 3-я | 3 | истина | 3 | 4 |
| 4-я | 4 | истина | 4 | 5 |
| 5-я | 5 | истина | 5 | 6 |
| 6-я | 6 | **ложь** | — | цикл кончился |

> [!important] Обрати внимание
> Проверок **шесть**, а проходов по телу — **пять**. Условие всегда проверяется на один раз больше, чем выполняется тело: последняя проверка и есть та, которая цикл останавливает. Из-за этого `i` после цикла равно 6, а не 5. На этом ловятся почти все ошибки «на единицу».

### Бесконечный цикл

Убери `i = i + 1`:

```cpp
int i = 1;
while (i <= 5) {
    std::cout << i << std::endl;   // печатает 1 бесконечно
}
```

`i` навсегда остаётся единицей, условие навсегда истинно. Программа будет сыпать «1» пока ты не нажмёшь **Ctrl+C** в терминале. Запусти это специально один раз — надо своими глазами увидеть и убить процесс руками, чтобы потом узнавать симптом.

## 4. `for` — то же самое, но компактно

В примере выше три части (`int i = 1`, `i <= 5`, `i = i + 1`) размазаны по трём разным местам: до цикла, в скобках, в конце тела. Их легко потерять — особенно третью. `for` собирает все три в одну строку:

```cpp
for (int i = 1; i <= 5; i++) {
    std::cout << i << std::endl;
}
```

Разбор по частям (разделены точками с запятой):

| часть | как называется | что делает | сколько раз выполняется |
|---|---|---|---|
| `int i = 1` | инициализация | создаёт `i` и кладёт в неё 1 | **один раз**, до всего остального |
| `i <= 5` | условие | проверяет, продолжать ли | перед каждым проходом → 6 раз |
| `i++` | шаг | увеличивает `i` на 1 | после каждого прохода → 5 раз |

### Точный порядок

Запомни цепочку — она объясняет любое поведение `for`:

```
инициализация → проверка → тело → шаг → проверка → тело → шаг → ... → проверка(ложь) → выход
```

> [!warning] Шаг выполняется ПОСЛЕ тела, а не до
> На первом проходе тело видит `i == 1`, а не 2. `i++` срабатывает только когда тело закончилось. Это вторая по частоте ошибка в понимании `for`.

### `i++` и что это такое

`i++` — это сокращение для `i = i + 1`. Есть ещё:

- `i--` → `i = i - 1` (обратный отсчёт)
- `i += 2` → `i = i + 2` (шаг через два — например, только чётные)
- `i *= 2` → `i = i * 2` (шаг с удвоением: 1, 2, 4, 8, 16... — привет, степени двойки)

Шаг вообще не обязан быть единицей. `for (int i = 10; i >= 1; i--)` — счёт вниз.

### Где живёт `i`

```cpp
for (int i = 1; i <= 5; i++) {
    // i здесь есть
}
// а здесь i уже НЕ существует — компилятор скажет 'i' was not declared
```

Переменная, объявленная в круглых скобках `for`, умирает вместе с циклом. Если значение нужно после цикла — объявляй до цикла:

```cpp
int i;
for (i = 1; i <= 5; i++) { }
std::cout << i;   // 6
```

## 5. `do-while` — сначала делаем, потом проверяем

```cpp
int n;
do {
    std::cout << "Введи положительное число: ";
    std::cin >> n;
} while (n <= 0);
```

Отличие от `while` одно: **тело гарантированно выполняется хотя бы раз**, потому что условие проверяется в конце. Логично — пока пользователь ничего не ввёл, проверять `n` бессмысленно, там мусор.

> [!note] Точка с запятой
> После `while (...)` в конце `do-while` **обязательна** точка с запятой. Единственное место в языке, где `while` заканчивается точкой с запятой.

### Когда какой цикл брать

| Ситуация | Цикл |
|---|---|
| Знаю точное число повторений (от 1 до N, по массиву) | `for` |
| Повторяю «пока условие верно», сколько шагов — заранее неизвестно | `while` |
| Надо выполнить минимум один раз (меню, проверка ввода) | `do-while` |

Жёсткого правила нет, любой цикл переписывается в любой другой. Это вопрос читаемости: `for` кричит «я знаю, сколько раз», `while` — «я не знаю, когда это кончится».

## 6. Накопители: главный приём в задачах на циклы

Половина задач дня сводится к одной схеме: **переменная вне цикла, которая копит результат**.

### Сумма — накопитель начинается с 0

```cpp
int n;
std::cin >> n;
int sum = 0;                       // ВНЕ цикла!
for (int i = 1; i <= n; i++) {
    sum = sum + i;                 // или sum += i;
}
std::cout << sum << std::endl;     // печатаем после цикла
```

Трассировка для `n = 4`:

| `i` | `sum` до | `sum` после |
|---|---|---|
| 1 | 0 | 1 |
| 2 | 1 | 3 |
| 3 | 3 | 6 |
| 4 | 6 | 10 |

### Произведение — начинается с 1

Факториал. Если начать с нуля, всё умножится на ноль и результат будет ноль:

```cpp
int fact = 1;                      // не 0!
for (int i = 1; i <= n; i++) {
    fact *= i;
}
```

### Счётчик — тоже с 0

«Сколько среди введённых чисел положительных»:

```cpp
int count = 0;
for (int i = 1; i <= n; i++) {
    int x;
    std::cin >> x;
    if (x > 0) count++;            // условие внутри цикла — норма
}
```

> [!important] Правило
> Накопитель объявляется **до** цикла, изменяется **внутри**, печатается **после**. Объявишь внутри — он будет сбрасываться на каждом проходе, и ты получишь мусор.

## 7. Разбор числа на цифры — ключ к задачам 13, 14, 15, 16

Здесь Дни 2 и 3 сходятся. Два инструмента из Дня 2:

- `n % 10` → **последняя цифра** числа. `123 % 10 == 3`
- `n / 10` → число **без последней цифры** (целочисленное деление!). `123 / 10 == 12`

Значит цифры можно «отщипывать» с конца, пока число не превратится в 0:

```cpp
int n = 123;
while (n > 0) {
    int digit = n % 10;    // взяли последнюю цифру
    std::cout << digit << " ";
    n = n / 10;            // отрезали её
}
// напечатает: 3 2 1
```

Трассировка:

| `n` до | `n % 10` | `n / 10` |
|---|---|---|
| 123 | 3 | 12 |
| 12 | 2 | 1 |
| 1 | 1 | 0 |
| 0 | условие ложно → выход | |

Почему `while`, а не `for`? Мы не знаем заранее, сколько в числе цифр. Классический случай для `while`.

Теперь смотри: этот же скелет — это сразу три задачи.

- **Сумма цифр** (№13): вместо печати — накопитель `sum += digit`.
- **Количество цифр** (№14): вместо печати — счётчик `count++`.
- **Переворот числа** (№15): накопитель `rev = rev * 10 + digit`. Подумай сам, почему именно так — это и есть зачёт дня, разбирать не буду.

> [!warning] Ловушка
> Если разбираешь `n` в цикле, ты его портишь — после цикла в `n` останется 0. Если исходное число нужно потом (например, для палиндрома — сравнить с перевёрнутым), сделай копию: `int copy = n;` и жуй копию.

## 8. Типичные ошибки — читай перед тем, как звать на помощь

| Код | Что происходит | Симптом |
|---|---|---|
| `for (int = 1; ...)` | нет имени переменной | ошибка компиляции, `expected unqualified-id` |
| `for (int i = 1; i <= 5; i++);` | лишняя `;` — тело пустое, цикл крутит воздух | цикл «не работает», печатает один раз |
| забыл `i++` | `i` не меняется | бесконечный цикл, Ctrl+C |
| `i < 5` вместо `i <= 5` | 4 прохода вместо 5 | не хватает последнего числа |
| `int sum = 0;` внутри цикла | сбрасывается каждый проход | сумма равна последнему числу |
| `int fact = 0;` | всё умножается на 0 | факториал всегда 0 |
| меняешь `i` внутри тела | шаг ломается | пропуски, повторы, зависание |
| `while (i = 5)` | `=` вместо `==` — присваивание вместо сравнения | бесконечный цикл |

> [!tip] Метод отладки без gdb
> Программа ведёт себя странно → рисуй таблицу трассировки на бумаге для маленького входа (`n = 3`, `n = 4`). В 9 случаях из 10 ошибка находится на второй строке таблицы. Второй приём — воткнуть в тело `std::cout << "i=" << i << " sum=" << sum << std::endl;` и посмотреть, что реально происходит.

## 11. Итог одной страницей

- Цикл = начальное состояние + условие продолжения + шаг изменения. Нет шага → бесконечный цикл.
- `while` — когда неизвестно число повторений. `for` — когда известно. `do-while` — когда нужен минимум один проход.
- Порядок в `for`: инициализация → проверка → тело → шаг → проверка → …
- Условие проверяется на один раз больше, чем выполняется тело.
- Накопитель: объявить до, менять внутри, печатать после. Сумма с 0, произведение с 1.
- `n % 10` — последняя цифра, `n / 10` — обрезать последнюю цифру. На этой паре стоят четыре задачи дня.
- Странное поведение → таблица трассировки на бумаге для `n = 3`.
