# День 8 — Функции

> [!abstract] О чём эта лекция
> Первая тема второй недели и первое настоящее облегчение за курс. Вчера ты написал программу на 150 строк и на собственном опыте узнал, каково это: чтобы понять строку 90, нужно помнить всё, что было в строках с 10 по 89. Функции решают именно эту проблему. Они не про экономию букв, они про то, чтобы перестать держать всю программу в голове одновременно.

---

## 1. Зачем это нужно именно сейчас

Твой вчерашний проект болен тремя вещами, и ты их видел своими глазами.

**Дублирование.** Проверка ввода написана в четырёх местах почти одинаково. Нашёл в ней ошибку, исправил в трёх, забыл в четвёртом.

**Невозможно проверить кусок отдельно.** Чтобы протестировать подсчёт среднего, надо запустить программу, выбрать пункт меню, ввести данные, дойти до нужного места. Каждый раз заново.

**Границы блоков существуют только в комментарии.** Ты пишешь `// считаем среднее`, и это единственное, что отделяет один смысловой кусок от другого. Компилятор про эту границу не знает, а значит она в любой момент может расплыться.

Функция даёт куску кода **имя** и **границу**. Граница важнее. Внутри функции видно только то, что ей передали, и это не ограничение, а именно то, что нужно: когда пишешь функцию, остальная программа тебя не касается, а когда пишешь остальную программу, внутренности функции тебя не касаются.

## 2. Анатомия функции

```cpp
int square(int x) {
    return x * x;
}
```

| Часть | Что это |
|---|---|
| `int` перед именем | тип возвращаемого значения: что функция отдаёт наружу |
| `square` | имя, по которому её вызывают |
| `(int x)` | список параметров: что она принимает и какого типа |
| `{ ... }` | тело, обычный код |
| `return x * x;` | результат, который уходит в точку вызова |

Вызов:

```cpp
int a = square(5);              // a == 25
std::cout << square(a + 1);     // считается 26, потом 676
```

Два слова, которые путают все:

- **Параметр** это переменная в объявлении функции (`int x`).
- **Аргумент** это конкретное значение при вызове (`5`).

Параметр это «место», аргумент это «что туда положили».

### Что происходит при вызове

1. Считаются аргументы (`a + 1` превращается в 26).
2. Значения **копируются** в параметры.
3. Управление уходит в тело функции.
4. `return` заканчивает функцию и подставляет результат на место вызова.
5. Программа продолжается со следующей операции.

Выражение `square(5)` после вызова ведёт себя как обычное число 25: его можно сложить, сравнить, напечатать, передать в другую функцию.

## 3. `void`: функции, которые ничего не возвращают

Не всякое действие даёт результат. Печать разделителя ничего не считает.

```cpp
void printLine(int n, char c) {
    for (int i = 0; i < n; i++) std::cout << c;
    std::cout << '\n';
}

printLine(30, '-');
```

`void` значит «возвращаемого значения нет». Такую функцию нельзя присвоить переменной, её только вызывают ради действия.

Внутри `void`-функции `return;` без значения тоже работает: он просто заканчивает её досрочно.

> [!important] Считать или печатать, но не одновременно
> ```cpp
> void printAverage(int a[], int n) {      // считает И печатает
>     ...
>     std::cout << sum / n;
> }
>
> double average(int a[], int n) {         // только считает
>     ...
>     return (double)sum / n;
> }
> ```
> Второй вариант почти всегда лучше. Результат можно напечатать, сравнить, положить в массив, передать дальше. Из первого варианта ничего не достать, кроме символов на экране, и проверить его можно только глазами. Правило простое: функция либо считает и возвращает, либо выводит. Смешивать значит терять и то и другое.

## 4. Объявление и определение: почему компилятор ругается

Компилятор читает файл сверху вниз и знает только то, что уже прочитал. Такой код не собирается:

```cpp
int main() {
    std::cout << square(5);      // ошибка: 'square' was not declared in this scope
}

int square(int x) { return x * x; }
```

Два решения. Первое: положить функцию выше `main`. Работает, но при десяти функциях порядок начинает диктовать структуру файла, и это неудобно.

Второе, нормальное: **прототип**, то есть объявление без тела.

```cpp
int square(int x);              // объявление, с точкой с запятой, тела нет
double average(int a[], int n);

int main() {
    std::cout << square(5);     // компилятор уже знает, что такое square
}

int square(int x) { return x * x; }    // определение
```

| | Объявление (прототип) | Определение |
|---|---|---|
| Как выглядит | заголовок и `;` | заголовок и тело в `{}` |
| Что сообщает | имя, типы параметров, тип результата | ещё и что функция делает |
| Сколько раз можно | сколько угодно | ровно один |

Прототипы наверху файла работают и как оглавление: видно все функции программы одним списком, без деталей. На следующих лекциях эти списки переедут в отдельные заголовочные файлы `.h`, и станет понятно, чем на самом деле занимался `#include` из первого дня: он вставлял в твой файл ровно такие объявления.

## 5. Аргументы это копии. Главный сюрприз дня

```cpp
void spoil(int x) {
    x = 100;                    // меняем параметр
}

int main() {
    int a = 5;
    spoil(a);
    std::cout << a;             // 5, а не 100
}
```

Функция получила не переменную `a`, а её **копию**. Всё, что происходит с параметром внутри, снаружи не видно вообще.

| Шаг | `a` в `main` | `x` в `spoil` |
|---|---|---|
| до вызова | 5 | не существует |
| вызов, копирование | 5 | 5 |
| `x = 100` | 5 | 100 |
| выход из функции | 5 | исчез |

Это называется передачей по значению, и это поведение по умолчанию для всех обычных типов. Отсюда правило: **чтобы функция повлияла на программу, она должна вернуть значение.**

```cpp
int increment(int x) { return x + 1; }

a = increment(a);      // вот так работает
```

> [!note] Дальше будет исключение
> Способ дать функции доступ к самой переменной, а не к копии, существует и называется передачей по ссылке. Отдельная тема, целиком в следующей лекции, вместе с ответом на неожиданный вопрос: почему массив, в отличие от `int`, при передаче в функцию **не** копируется. Сегодня достаточно твёрдо усвоить поведение по умолчанию, иначе исключение не с чем будет сравнивать.

## 6. Область видимости и время жизни

Переменная, объявленная внутри функции, называется локальной. Она рождается при входе и исчезает при выходе.

```cpp
int f() {
    int count = 0;      // новая переменная при каждом вызове
    count++;
    return count;       // всегда 1
}
```

Ни одна функция не видит локальных переменных другой. Даже если они называются одинаково, это разные переменные в разных местах памяти.

```cpp
int square(int x) { return x * x; }

int main() {
    int x = 10;
    std::cout << square(3);     // внутри square свой x, равный 3
    std::cout << x;             // 10, ничего не изменилось
}
```

Это ровно то же правило, что уже встречалось в четвёртой лекции с затенением счётчиков во вложенных циклах, только теперь оно работает на тебя: имена внутри функций можно выбирать свободно, не думая, что занято в остальной программе.

> [!important] Почему нельзя вернуть локальный массив
> Забегая вперёд: локальный массив тоже исчезает при выходе из функции, а вот вернуть «указатель на него» технически можно, и это одна из самых неприятных ошибок в C++, потому что программа при этом обычно продолжает работать. Пока просто запомни симптом на будущее: если функция должна отдать массив, массив создаётся снаружи и передаётся внутрь, а не создаётся внутри и отдаётся наружу. Подробно на уровне памяти, лекции 15-16.

## 7. Глобальные переменные: почему их не надо

Переменную можно объявить вне всех функций, и тогда её видят все.

```cpp
int total = 0;          // глобальная

void add(int x) { total += x; }
```

Выглядит удобно: не надо ничего передавать и возвращать. Но исчезает то, ради чего функции и заводились, а именно граница. Функцию `add` больше нельзя прочитать отдельно от программы: чтобы понять, что она делает, надо знать, кто ещё в целой программе трогает `total`. Появляется ошибка «значение не то» и искать её приходится во всех местах сразу.

Правило на всю первую неделю с функциями: **всё, что функции нужно, передаётся параметрами, всё, что она произвела, отдаётся через `return`.** Глобальные константы (`const int MAX = 100;`) это другое дело, они не меняются, и с ними проблем нет.

## 8. `return` и ранний выход

`return` заканчивает функцию немедленно, как `break` заканчивает цикл. Их может быть несколько.

```cpp
bool isValidTriangle(double a, double b, double c) {
    if (a <= 0 || b <= 0 || c <= 0) return false;      // отсеяли мусор
    if (a + b <= c) return false;
    if (a + c <= b) return false;
    if (b + c <= a) return false;
    return true;                                      // всё проверено
}
```

Так писать лучше, чем заворачивать всё в один огромный `if` с четырьмя `&&`: каждая проверка стоит отдельно, читается отдельно и правится отдельно. Приём тот же самый, что `continue` в четвёртой лекции, только теперь он выходит не из прохода цикла, а из функции.

> [!warning] Не-void функция обязана вернуть значение на любом пути
> ```cpp
> int sign(int x) {
>     if (x > 0) return 1;
>     if (x < 0) return -1;
> }                                  // а если x == 0?
> ```
> Компилятор с `-Wall` предупредит («control reaches end of non-void function»), а если предупреждение проигнорировать, функция вернёт мусор. Проверяй все ветки: любой путь исполнения должен заканчиваться `return`.

## 9. `main` это тоже функция

Теперь видно, что `int main()` из первого дня не магическое заклинание, а обычная функция: тип результата `int`, пустой список параметров, тело в скобках. И `return 0` наконец имеет смысл: это возвращаемое значение, тот самый код завершения, который читает `echo $?` и по которому `&&` в терминале решает, запускать ли следующую команду.

Отличие только в том, что `main` вызывает не твой код, а операционная система, и потому она одна на программу.

## 10. Как разрезать программу на функции

Самый частый вопрос дня: где проводить границы. Пять признаков, что кусок пора выносить.

1. **Ты можешь назвать его глаголом.** `readValidNumber`, `printMenu`, `calculateAverage`, `isPrime`. Не получается назвать значит границу выбрал не там.
2. **Он делает ровно одно дело.** Если в имени приходится вставлять «и» (`readAndCheckAndSave`), это три функции.
3. **Он встречается больше одного раза.** Второе повторение уже повод, третье это обязанность.
4. **Он длиннее пятнадцати строк.** Не закон, а сигнал: почти всегда внутри спрятаны две операции.
5. **Ему нужно мало входных данных.** Три-четыре параметра максимум. Если требуется семь, значит функция взяла на себя чужую работу.

Хорошее имя это половина дела. `check(int x)` не говорит ничего, `isPrime(int n)` говорит всё. Для функций, возвращающих `bool`, стандарт это префикс `is` или `has`.

### Показательный пример: ромб

Ромб из четвёртой лекции был зачётом дня и мучил всех. Смотри, что с ним делается, когда есть функции:

```cpp
void printPyramid(int n);           // уже написана в Дне 4
void printInvertedPyramid(int n);   // тоже

void printRhombus(int n) {
    printPyramid(n);
    printInvertedPyramid(n - 1);
}
```

Задача, которая занимала полчаса и три попытки, превратилась в две строки. Ничего нового в языке для этого не понадобилось: изменилось только то, что у частей появились имена и границы. Вот это и есть декомпозиция, и вот зачем она нужна.

## 11. Функция как место проверки

Полезный побочный эффект границы: проверять входные данные становится возможно **в одном месте**.

```cpp
int readNumberInRange(int lo, int hi) {
    int x;
    while (true) {
        std::cout << "Введи число от " << lo << " до " << hi << ": ";
        if (!(std::cin >> x)) {
            std::cin.clear();
            std::cin.ignore(10000, '\n');
            continue;
        }
        if (x < lo || x > hi) continue;
        return x;                     // сюда попадает только корректное значение
    }
}
```

Вчера эта проверка была размазана по четырём местам меню. Сегодня она одна, и после её вызова остальная программа может считать данные корректными.

> [!note] Про твою специальность
> Такая функция называется точкой валидации, и по ней проводят границу доверия: снаружи данные считаются грязными, внутри уже проверенными. Практически все уязвимости, связанные с вводом, живут там, где такой границы нет и каждый участок кода проверяет данные как умеет (или не проверяет, полагая, что проверил сосед). Привычка «данные из внешнего мира проходят через одну функцию» стоит дороже, чем кажется на программе в 150 строк.

## 12. Как отлаживать функции

Функции упрощают отладку сильнее, чем что-либо другое из первой недели.

**Проверяй по одной, отдельно от программы.** Написал `digitSum` и не уверен: заведи временный `main` из трёх строк и вызови её на 0, 5, 123, 100000 и отрицательном числе. Никакого меню, никакого ввода. Работает значит закрыли и забыли.

**Печатай вход и выход.** На время отладки первой строкой в теле:

```cpp
std::cout << "[digitSum(" << n << ")]\n";
```

Так видно, что функция получила. Половина ошибок оказывается не внутри функции, а в том, что ей передали не то, что ты думал.

**Локализация становится дешёвой.** Программа из двенадцати функций, каждая проверена отдельно, ломается предсказуемо: ошибка либо внутри одной функции, либо в порядке их вызова. Это два коротких списка вместо одного длинного.

## 13. Типичные ошибки

| Код или ситуация | Что происходит | Симптом |
|---|---|---|
| вызов до объявления | компилятор не знает имени | `'square' was not declared in this scope` |
| у прототипа забыта `;`, или у определения лишняя | путаница объявления и определения | ошибки, текст которых не похож на причину |
| не-void функция без `return` на каком-то пути | возвращается мусор | результат меняется от запуска к запуску |
| изменение параметра в надежде повлиять на переменную | менялась копия | «функция ничего не делает» |
| функция и считает, и печатает | результат недоступен | приходится копировать код, чтобы использовать значение |
| функция объявлена внутри другой функции | так нельзя | ошибка компиляции с непонятным текстом |
| `void f()` вызывается как `int x = f();` | значения нет | `void value not ignored as it ought to be` |
| глобальная переменная вместо параметра | границы нет | ошибку приходится искать по всей программе |
| два `return` подряд | второй никогда не выполнится | `-Wall` предупредит о недостижимом коде |
| имя функции совпало с именем переменной | затенение | компилятор ругается там, где всё выглядит верно |

> [!tip] Как переписывать, чтобы не сломать
> Не переписывай всё сразу. Выноси по одной функции и после каждой прогоняй тест-кейсы и делай коммит. Тогда в момент, когда что-то сломается, у тебя будет работающая предыдущая версия и `git diff` длиной в одну функцию. Это тот же принцип маленьких шагов, что вчера, и он работает при рефакторинге даже лучше, чем при написании с нуля.

## 16. Итог одной страницей

- Функция даёт куску кода имя и границу. Граница важнее: внутри видно только переданное, снаружи не видно внутреннего.
- Анатомия: тип результата, имя, параметры, тело, `return`. Параметр это место, аргумент это значение.
- `void` значит «ничего не возвращает». Такая функция вызывается ради действия.
- Функция либо считает и возвращает, либо печатает. Смешивать значит терять возможность использовать результат.
- Компилятор читает сверху вниз. Прототип наверху, определение ниже, и порядок функций перестаёт иметь значение.
- Аргументы копируются. Изменение параметра снаружи не видно. Повлиять на программу можно через `return`.
- Локальные переменные исчезают при выходе. Имена внутри разных функций не конфликтуют.
- Глобальные переменные ломают границу, ради которой всё затевалось. Данные внутрь через параметры, результат наружу через `return`.
- `return` может быть несколько: ранний выход из функции читается лучше, чем один большой `if`.
- Не-void функция обязана вернуть значение на каждом пути исполнения.
- `main` это обычная функция, а `return 0` это код завершения из первого дня.
- Резать по признакам: называется глаголом, делает одно дело, повторяется, короче пятнадцати строк, мало параметров.
- Ввод из внешнего мира проходит через одну функцию-валидатор, а не проверяется в каждом месте по-своему.
- Отлаживать по одной функции, на трёх-четырёх входах, отдельным `main` из трёх строк.
