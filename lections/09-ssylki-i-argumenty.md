# День 9 — Ссылки и передача аргументов

> [!abstract] О чём эта лекция
> Вчера было правило: аргументы копируются, и функция не может изменить переменную вызывающего кода. Сегодня к нему появляется исключение, и это одна из центральных вещей в C++. Ссылка даёт функции доступ к самой переменной, а не к копии. Заодно разберём, почему массив ведёт себя не как `int` и молча позволяет функции испортить твои данные, и как от этого защищает `const`. В конце два мелких удобства: перегрузка и параметры по умолчанию.

---

## 1. Задача, которая вчера не решалась

Классика: поменять значения двух переменных местами.

```cpp
void badSwap(int a, int b) {
    int t = a;
    a = b;
    b = t;
}

int x = 1, y = 2;
badSwap(x, y);
std::cout << x << " " << y;      // 1 2, ничего не поменялось
```

Функция честно всё обменяла, но обменяла **копии**, а они исчезли на выходе.

| Шаг | `x` | `y` | `a` в функции | `b` в функции |
|---|---|---|---|---|
| до вызова | 1 | 2 | нет | нет |
| копирование | 1 | 2 | 1 | 2 |
| обмен внутри | 1 | 2 | 2 | 1 |
| выход | 1 | 2 | исчезли | исчезли |

`return` не спасает: он отдаёт одно значение, а изменить надо два. Значит нужен способ дать функции не копию, а доступ к самой переменной.

## 2. Ссылка: второе имя той же переменной

```cpp
int x = 5;
int& r = x;      // r это не новая переменная, это второе имя для x

r = 10;
std::cout << x;  // 10
x = 20;
std::cout << r;  // 20
```

`int&` читается как «ссылка на `int`». Никакой копии не создаётся: `r` и `x` это одно и то же место в памяти под двумя именами.

| | Копия | Ссылка |
|---|---|---|
| Объявление | `int c = x;` | `int& r = x;` |
| Своё место в памяти | да | нет |
| Изменение влияет на `x` | нет | да |
| Можно объявить без значения | да | нет, обязательна инициализация |
| Можно потом привязать к другой переменной | не про неё | нет, никогда |

Два правила, которые вытекают из «это просто другое имя»:

**Ссылку обязательно инициализировать сразу.** `int& r;` не компилируется, потому что имя обязано что-то обозначать.

**Ссылку нельзя перенаправить.** Если после `int& r = x;` написать `r = y;`, это не привяжет `r` к `y`, а запишет значение `y` в `x`. Привязка делается один раз и навсегда.

> [!note] Один символ, два смысла
> `&` в C++ означает разное в зависимости от места. В объявлении типа (`int& r`) это ссылка. Перед именем переменной в выражении (`&x`) это взятие адреса, и оно относится к указателям, тема лекции 15. Плюс есть `&&` из второй лекции, логическое И. Один и тот же символ, три разные роли: смотри на контекст, а не на символ.

## 3. Передача по ссылке

Тот же `&` в списке параметров означает: параметр это не копия, а второе имя аргумента.

```cpp
void increment(int& x) {
    x++;
}

int a = 5;
increment(a);
std::cout << a;      // 6
```

И правильный обмен:

```cpp
void swap(int& a, int& b) {
    int t = a;
    a = b;
    b = t;
}
```

Сравнение бок о бок, оно того стоит:

| | `void f(int x)` | `void f(int& x)` |
|---|---|---|
| Что получает функция | копию значения | доступ к самой переменной |
| Изменения видны снаружи | нет | да |
| Стоимость передачи | копирование | ничего не копируется |
| Как выглядит вызов | `f(a)` | `f(a)`, точно так же |

Последняя строка важная и неприятная. **По вызову не видно, изменится переменная или нет.** `f(a)` выглядит одинаково в обоих случаях, и чтобы узнать правду, надо посмотреть на объявление функции.

> [!important] Отсюда требование к именам
> Раз вызов не выдаёт себя, за понятность отвечает имя. `swap(x, y)`, `sortArray(a, n)`, `readInto(value)` сразу говорят, что аргумент изменится. А `check(x)` или `process(a)` не говорят ничего, и через месяц ты сам не будешь помнить, портит эта функция свой аргумент или нет.

## 4. Как вернуть два значения

Теперь решается задача, которая вчера была тупиком: минимум и максимум за один проход.

```cpp
void minMax(const int a[], int n, int& mn, int& mx) {
    mn = a[0];
    mx = a[0];
    for (int i = 1; i < n; i++) {
        if (a[i] < mn) mn = a[i];
        if (a[i] > mx) mx = a[i];
    }
}

int lo, hi;
minMax(arr, n, lo, hi);      // после вызова в lo и hi лежат ответы
```

Параметры `mn` и `mx` называют выходными: функция не читает их, а записывает в них результат. Принятый порядок такой: сначала входные параметры, потом выходные. Так читается привычнее.

Ещё один полезный образец, тот же приём в другой роли:

```cpp
bool readNumber(int& out) {
    if (!(std::cin >> out)) {
        std::cin.clear();
        std::cin.ignore(10000, '\n');
        return false;         // не получилось
    }
    return true;              // получилось, значение в out
}

int x;
if (readNumber(x)) { /* работаем с x */ }
```

Через `return` уходит «удалось или нет», через ссылку сам результат. Такой вид функции встречается в C++ постоянно.

> [!note] Позже будет способ лучше
> Когда появятся структуры (лекция 18), два связанных результата можно будет вернуть одним `return`, упаковав их вместе. Это чище, чем выходные параметры, потому что видно, что функция возвращает результат, а не редактирует чужие переменные. Но выходные параметры от этого не исчезнут: их полно в реальном коде и в системных библиотеках, так что понимать надо оба способа.

## 5. Массив в функции: он не копируется

Самое неожиданное за день.

```cpp
void spoil(int a[], int n) {
    a[0] = 999;
}

int arr[3] = {1, 2, 3};
spoil(arr, 3);
std::cout << arr[0];      // 999
```

Никаких `&` нигде нет, а массив вызывающего изменился. Так и есть: **массивы в функции не копируются никогда.** В параметр попадает не сам массив, а информация о том, где он лежит. Функция работает с твоей памятью напрямую.

Полное объяснение будет в лекции 17, когда появятся указатели, а последствия важны уже сегодня, их три.

**Первое: размер внутри функции неизвестен.** Поэтому `n` передаётся отдельным параметром, всегда. В шестой лекции это было правилом, теперь понятна причина: `sizeof(a)` внутри функции даст размер не массива, а того самого «где он лежит», то есть 8 байт независимо от количества элементов.

**Второе: любая функция может испортить твои данные.** Причём тихо, и по вызову это не видно совсем.

**Третье: массив нельзя вернуть из функции.** Локальный массив исчезает на выходе. Работает другой порядок: массив создаётся снаружи, передаётся внутрь и там заполняется.

```cpp
void fillRandom(int a[], int n, int lo, int hi);      // так

int arr[100];
fillRandom(arr, 20, 1, 100);
```

| | `int x` | `int a[]` |
|---|---|---|
| Копируется при передаче | да | нет |
| Функция может изменить оригинал | только с `&` | всегда |
| Размер известен внутри | вопрос не имеет смысла | нет, нужен отдельный параметр |
| Можно вернуть из функции | да | нет |

## 6. `const`: запрет на изменение, который проверяет компилятор

Если функция массив только читает, скажи это прямо:

```cpp
double average(const int a[], int n) {
    long long sum = 0;
    for (int i = 0; i < n; i++) sum += a[i];
    // a[0] = 0;      // не скомпилируется, и это хорошо
    return (double)sum / n;
}
```

`const` перед типом параметра означает «через этот параметр менять нельзя». Попытка записи не пройдёт компиляцию.

Зачем это нужно, если ты и так не собирался ничего менять:

1. **Компилятор превращается в проверку.** Опечатка `=` вместо `==` внутри функции перестаёт быть тихой порчей данных и становится ошибкой сборки.
2. **Это документация, которая не устаревает.** По одному заголовку `double average(const int a[], int n)` видно: функция читает и ничего не портит. Комментарий про то же самое может соврать, `const` не может.
3. **Так меньше подозреваемых при отладке.** Данные испортились, а половина функций объявлена с `const`, значит вся эта половина автоматически невиновна.

### Как передавать: сводная таблица

| Что передаём | Как | Почему |
|---|---|---|
| `int`, `double`, `char`, `bool`, менять не надо | по значению: `int x` | копия стоит ничего, безопасно |
| то же, но функция должна изменить | `int& x` | нужен доступ к самой переменной |
| массив, только читаем | `const int a[]` | копии всё равно нет, `const` защищает |
| массив, надо изменить или заполнить | `int a[]` | так работает заполнение |
| большие данные, только читаем | `const T&` | лекции 12, 13, 18: строки, векторы, структуры |

Последняя строка про будущее, но привычку заводи сейчас. Когда появятся `std::string` и `std::vector`, передача их по значению начнёт стоить реального копирования, и `const T&` станет стандартным способом передавать что угодно тяжёлое.

## 7. Перегрузка функций

В C++ несколько функций могут носить одно имя, если различаются списком параметров.

```cpp
int maxOf(int a, int b)          { return a > b ? a : b; }
double maxOf(double a, double b) { return a > b ? a : b; }
int maxOf(int a, int b, int c)   { return maxOf(maxOf(a, b), c); }
```

Компилятор смотрит на типы и количество аргументов в точке вызова и выбирает подходящий вариант сам. `maxOf(2, 3)` пойдёт в первый, `maxOf(2.5, 3.5)` во второй, `maxOf(1, 2, 3)` в третий.

Зачем: одно и то же действие для разных типов логично называть одинаково. Без перегрузки пришлось бы держать `maxOfInt`, `maxOfDouble`, `maxOfThree`, и вызывающий код читался бы хуже.

> [!warning] Тип возвращаемого значения не участвует в выборе
> ```cpp
> int f(int x);
> double f(int x);      // ошибка компиляции, а не перегрузка
> ```
> Различать варианты можно только параметрами. Причина в том, что компилятор выбирает функцию по аргументам в момент вызова, а результат может быть просто отброшен (`f(5);` отдельной строкой), и выбирать было бы не по чему.

> [!warning] Неоднозначный вызов
> ```cpp
> maxOf(1, 2.5);      // call of overloaded 'maxOf(int, double)' is ambiguous
> ```
> Оба варианта подходят одинаково плохо: в первом надо превратить `2.5` в `int`, во втором `1` в `double`. Компилятор не угадывает, а сообщает о неоднозначности. Лечится приведением на месте вызова: `maxOf(1.0, 2.5)`.

Совет по мере: перегружай, когда варианты делают **одно и то же** для разных типов. Если функции делают разное, разные имена честнее, иначе читатель будет вынужден каждый раз проверять, какая версия вызвалась.

## 8. Параметры по умолчанию

Значение параметра можно задать заранее, и тогда его позволено не передавать.

```cpp
void printLine(int n = 30, char c = '-');

printLine();              // 30 дефисов
printLine(10);            // 10 дефисов
printLine(10, '=');       // 10 знаков равенства
```

Три правила, каждое из которых нарушают в первый же день.

**Умолчания только у последних параметров.** Пропускать аргументы можно лишь с конца: как компилятору понять `printLine(, '=')`, если первый пропущен, а второй передан. Поэтому `void f(int a = 1, int b)` не компилируется.

**Значение указывается один раз, в объявлении.** Если у функции есть прототип, умолчание пишется в нём, а в определении не повторяется:

```cpp
void printLine(int n = 30, char c = '-');          // здесь

void printLine(int n, char c) { ... }              // здесь без умолчаний
```

Повторишь в обоих местах, получишь `default argument given for parameter 1`. Текст ошибки, кстати, честный, надо просто знать, что он про это.

**Осторожно с перегрузкой.** Если рядом живут `void printLine()` и `void printLine(int n = 30)`, то вызов `printLine()` подходит обоим, и компилятор сообщит о неоднозначности. Умолчания и перегрузка одного имени плохо совмещаются, выбирай что-то одно.

## 9. Отладка: кто испортил данные

Новая категория ошибок, которой раньше не было: значение изменилось, а ты не понимаешь, где именно.

Порядок поиска:

1. **Выпиши подозреваемых.** Испортиться могло только через функции, принимающие эту переменную по ссылке, и через любые функции, принимающие массив.
2. **Проверь `const`.** Всё, что объявлено с `const`, из списка вычёркивается сразу, компилятор за это отвечает. Если функций с `const` мало, самое время расставить, польза окупится в первый же час.
3. **Печатай до и после вызова.**
   ```cpp
   std::cout << "before: " << a[0] << "\n";
   doSomething(a, n);
   std::cout << "after:  " << a[0] << "\n";
   ```
   Метод грубый, зато сразу отвечает на вопрос, кто виноват, вызывающий код или функция.
4. **Собирай с санитайзером.** Если функция вылезла за границы переданного массива, `-fsanitize=address` покажет это точно и с номером строки. Внутри функции размер неизвестен, значит `n` могли передать неправильно, и это очень частая ошибка дня.

> [!tip] Правило, которое стоит завести сегодня
> Пишешь функцию, которая принимает массив: первое, что делаешь, решаешь, будет она его менять или нет. Не будет значит `const` ставится сразу, не потом. Через неделю в программе будет двадцать функций, и расставлять `const` задним числом уже утомительно.

## 10. Типичные ошибки

| Код или ситуация | Что происходит | Симптом |
|---|---|---|
| `void swap(int a, int b)` без `&` | меняются копии | «функция ничего не делает» |
| `swap(&x, &y)` при параметрах-ссылках | передан адрес вместо переменной | ошибка компиляции про несовпадение типов |
| `int& r;` | ссылка без привязки | `declared as reference but not initialized` |
| `r = y;` в надежде перепривязать ссылку | записалось значение в исходную переменную | тихо неверные данные |
| `int& r = 5;` | ссылка на литерал | ошибка компиляции, тут нужна `const int&` |
| возврат ссылки на локальную переменную | она уже исчезла | иногда работает, иногда мусор, подробно в лекции 16 |
| `sizeof(a)` внутри функции | размер не массива | среднее и суммы считаются по неверному `n` |
| забыли передать `n` или передали не тот | функция ходит за границы | падение или мусор, санитайзер укажет место |
| read-only функция без `const` | компилятор не помогает | опечатка `=` вместо `==` портит данные молча |
| перегрузка только по типу результата | так нельзя | `ambiguating new declaration` |
| `maxOf(1, 2.5)` | оба варианта равно плохи | `call of overloaded ... is ambiguous` |
| умолчание и в объявлении, и в определении | задано дважды | `default argument given for parameter 1` |
| умолчание не у последнего параметра | пропуск невозможен | `default argument missing for parameter 2` |

## 13. Итог одной страницей

- Ссылка это второе имя существующей переменной. Своей памяти у неё нет, инициализация обязательна, перепривязать нельзя.
- Параметр-ссылка (`int& x`) даёт функции доступ к самой переменной. Изменения видны снаружи.
- Вызов выглядит одинаково при передаче по значению и по ссылке, поэтому за понятность отвечает имя функции.
- Два результата возвращают через выходные параметры-ссылки. Входные параметры идут первыми, выходные последними.
- Образец `bool readNumber(int& out)`: успех через `return`, значение через ссылку.
- Массивы в функции не копируются никогда. Отсюда: размер передаётся отдельно, функция может испортить твои данные, вернуть массив нельзя.
- `sizeof` внутри функции даёт не размер массива. Это причина, по которой `n` был обязателен ещё в шестой лекции.
- `const` в параметре запрещает изменение, и проверяет это компилятор. Ставится сразу, а не задним числом.
- Правило передачи: мелкое по значению, мелкое с изменением по ссылке, массив только с `const`, если читаем, тяжёлое через `const&`.
- Перегрузка различает функции по параметрам, но не по типу результата. Смешение `int` и `double` в аргументах даёт неоднозначность.
- Умолчания только у последних параметров, задаются один раз в объявлении, плохо совмещаются с перегрузкой.
- Отладка порчи данных: список подозреваемых из функций со ссылками и массивами, минус все, помеченные `const`, плюс печать до и после вызова.
