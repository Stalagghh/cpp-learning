## Чем это отличается от учебника

**Ошибки разбираются наравне с материалом.** В каждой лекции есть таблица «типичная ошибка, что происходит, по какому симптому узнать». Не «так делать нельзя», а «вот как это будет выглядеть у тебя на экране».

**Таблицы трассировки.** Главный инструмент отладки без отладчика: расписать по шагам, что лежит в переменной. Появляются в третьей лекции и дальше используются постоянно.

**Зачёт дня вместо галочки.** У каждого дня есть одна задача, по которой видно, понята тема или нет. Её решение в лекциях специально не приводится. Даются инструменты и метод, а код пишешь ты.

**«Проверь себя» в конце каждой лекции.** Если на вопрос не получается ответить своими словами, не подглядывая, тема не закрыта, сколько бы задач ни было решено.

**Темы связаны между собой.** Целочисленное деление из второй лекции оказывается половиной задач третьей. Ошибка `max = 0` из пятой всплывает в шестой. Материал не рассыпается на независимые главы.

**Уклон в информационную безопасность там, где он уместен.** Переполнение `int`, неопределённое поведение и выход за границы массива разбираются как то, чем они являются в реальности, а не как «ошибки новичка». Я учусь по специальности «информационная безопасность», отсюда акценты.

## Для кого

Для начинающих с нуля, кому нужен не только синтаксис, но и понимание, что происходит под капотом. Для студентов, которым C++ дали первым серьёзным языком. Для тех, кто писал на Python или JS и спотыкается на типах и памяти. 

## Как заниматься

Порядок строгий, с 01 по 07. Каждая лекция опирается на предыдущие и прямо на них ссылается.

На каждый день:

1. Прочитать лекцию целиком, а не по частям. Связки между темами тут несущие.
2. Ответить на вопросы из «Проверь себя» вслух или на бумаге. Не мысленно: мысленно всегда кажется, что понятно.
3. Решить все задачи дня, по порядку, каждую отдельным файлом.
4. Зачётную задачу сделать самому. Её одну нельзя списывать, остальное можно.
5. Закрыть день коммитом (по желанию, конечно же).

Правила, на которых всё держится:

* **3-4 часа в день, каждый день.** Час ежедневно сильнее, чем восемь часов раз в неделю.
* **Правило 20 минут.** Бьёшься сам 20 минут, потом ищешь помощь. Не раньше и не позже.
* **Ошибки компилятора читать, а не пугаться.** Первая строка ошибки самая важная, остальные обычно её следствия.
* **Собирать с `-Wall -Wextra`.** Ловит большую часть глупых ошибок до запуска.
* **Каждый день заканчивается коммитом.** История коммитов это доказательство регулярности, в первую очередь для себя.

За неделю выходит около сотни решённых задач и один работающий проект.

Три способа всё испортить: смотреть видео вместо написания кода, списывать решение не промучившись самому, пропустить день «потому что устал». Пропущенный день почти всегда становится двумя.

## Как читать файлы

Лекции написаны под [Obsidian](https://obsidian.md/): с коллаутами, ссылками вида `[[02-tipy-i-vetvleniya]]` и формулами.

На GitHub всё читается нормально, но часть коллаутов покажется обычными цитатами, а внутренние ссылки работать не будут. Если хочется полного вида и графа связей между лекциями, клонируйте репозиторий и откройте папку как хранилище Obsidian:

```bash
git clone https://github.com/Stalagghh/cpp-learning.git
```

## Окружение

Всё нужное есть в первой лекции. Кратко, для Linux:

```bash
sudo apt update
sudo apt install build-essential g++ gdb git
g++ --version
```

Сборка и запуск:

```bash
g++ -std=c++17 -Wall -Wextra -g hello.cpp -o hello && ./hello
```

На дне с массивами добавьте санитайзер, он показывает выход за границы сразу, а не через неделю:

```bash
g++ -std=c++17 -Wall -Wextra -g -fsanitize=address,undefined 01.cpp -o 01
```
