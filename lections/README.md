# C++ с нуля — конспекты первой недели

Шесть лекций, которые проводят человека от «никогда не компилировал программу» до «написал сортировку своими руками». Не пересказ справочника, а разбор того, где именно спотыкаются на старте — и почему.

Писалось для себя, во время собственного обучения. Выкладываю, потому что таких конспектов мне самому не хватало: учебники объясняют, **как** устроен язык, и почти никогда — **на чём** ты сломаешься через десять минут после прочтения главы.

## Чем это отличается от учебника

- **Ошибки разбираются наравне с материалом.** В каждой лекции есть таблица «типичные ошибки → что происходит → по какому симптому узнать». Не «так делать нельзя», а «вот как это будет выглядеть на экране, когда ты это сделаешь».
- **Таблицы трассировки.** Главный инструмент отладки без отладчика: расписать по шагам, что лежит в переменной. Появляется в лекции 3 и дальше используется постоянно.
- **Зачёт дня вместо галочки.** У каждого дня есть одна задача, по которой видно, понята тема или нет. Её решение в лекциях **не приводится** — намеренно. Даются инструменты и метод, а код пишешь ты.
- **«Проверь себя» своими словами.** Список вопросов в конце каждой лекции. Если на вопрос не получается ответить без подглядывания — тема не закрыта, сколько бы задач ни было решено.
- **Связки между темами.** `%` и целочисленное деление из лекции 2 внезапно оказываются половиной задач лекции 3. Ошибка `max = 0` из лекции 5 всплывает в лекции 6. Материал не рассыпается на независимые главы.
- **Уклон в информационную безопасность там, где он естественный.** Переполнение `int`, неопределённое поведение, выход за границы массива разбираются не как «ошибки новичка», а как то, чем они являются в реальности. Автор учится по специальности «информационная безопасность автоматизированных систем», отсюда акценты.

## Как этим пользоваться

**Порядок строгий: 01 → 07.** Каждая лекция опирается на предыдущие и прямо на них ссылается.

На каждый день:

1. Прочитать лекцию целиком. Не по частям — иначе теряются связки, а они здесь несущие.
2. Ответить на вопросы из раздела «Проверь себя» **своими словами, вслух или на бумаге**. Не мысленно: мысленно всегда кажется, что понятно.
3. Решить задачи дня — все, по порядку, каждую отдельным файлом.
4. Сделать зачётную задачу самостоятельно. Именно её нельзя списывать, всё остальное — можно.
5. Закрыть день коммитом.

Правила, на которых всё держится:

- **3–4 часа в день, каждый день.** Регулярность бьёт интенсивность: час каждый день сильнее восьми часов раз в неделю.
- **Правило 20 минут.** Бьёшься сам 20 минут → потом ищешь помощь. Не раньше и не позже.
- **Ошибки компилятора читать, а не пугаться.** Первая строка ошибки — самая важная, остальные обычно её следствия.
- **Собирать с `-Wall -Wextra`.** Ловит большую часть глупых ошибок до запуска.
- **Каждый день заканчивается коммитом.** История коммитов — доказательство регулярности, в первую очередь для себя.

За неделю получается около 100 решённых задач и один работающий проект.

## Формат файлов

Лекции — обычный Markdown, написанный под [Obsidian](https://obsidian.md/): с коллаутами (`> [!warning]`), внутренними ссылками `[[02-tipy-i-vetvleniya]]` и формулами в `$...$`.

Читать можно тремя способами:

| Способ | Что работает | Что нет |
|---|---|---|
| Прямо на GitHub | текст, таблицы, код, часть коллаутов | `[[вилкалинки]]`, коллауты вроде `abstract` и `question` — покажутся обычными цитатами |
| Клонировать в хранилище Obsidian | всё, включая граф связей между лекциями | — |
| Любой редактор Markdown | текст, таблицы, код | коллауты и вилкалинки |

Рекомендуемый способ — второй:

```bash
git clone https://github.com/<пользователь>/<репозиторий>.git
```

и открыть папку как хранилище Obsidian. Лекции ссылаются друг на друга, и в графе видно, как темы связаны.

## Как выглядит материал

Фрагмент из лекции 3 — трассировка цикла `while (i <= 5)`:

| проверка | `i` | `i <= 5` | что напечатано | `i` после тела |
|---|---|---|---|---|
| 1-я | 1 | истина | 1 | 2 |
| … | … | … | … | … |
| 5-я | 5 | истина | 5 | 6 |
| 6-я | 6 | **ложь** | — | цикл кончился |

> Проверок шесть, а проходов по телу — пять. Условие всегда проверяется на один раз больше, чем выполняется тело: последняя проверка и есть та, которая цикл останавливает. Из-за этого `i` после цикла равно 6, а не 5. На этом ловятся почти все ошибки «на единицу».

Примерно так устроены все шесть лекций: сначала механика, потом почему именно так, потом где на этом ломаются.

## Окружение

Всё, что нужно, есть в лекции 01. Кратко, для Linux:

```bash
sudo apt update
sudo apt install build-essential g++ gdb git
g++ --version
```

Сборка и запуск:

```bash
g++ -std=c++17 -Wall -Wextra -g hello.cpp -o hello && ./hello
```

Для дня с массивами — обязательно с санитайзером, он показывает выход за границы сразу, а не через неделю:

```bash
g++ -std=c++17 -Wall -Wextra -g -fsanitize=address,undefined 01.cpp -o 01
```

## Три способа убить первую неделю

1. **Смотреть видеоуроки вместо написания кода.** Иллюзия прогресса без навыка. На час чтения или просмотра — два часа своего кода.
2. **Копировать решение, не промучившись сам.** Задача, которую ты списал, не решена.
3. **Пропустить день «потому что устал».** Пропущенный день почти всегда становится двумя.

## Ошибки, замечания, помощь

Конспекты писал студент во время собственного обучения — значит, ошибки в них есть. Нашли неточность, кривую формулировку или место, где объяснение не работает, — открывайте issue. Это полезнее, чем кажется: место, на котором споткнулся читатель, почти всегда означает, что там пропущен один шаг объяснения.

Pull request'ы с исправлениями приветствуются. Просьба сохранять формат: коллауты, таблицы трассировки, раздел «Проверь себя», и не приводить решения зачётных задач.
