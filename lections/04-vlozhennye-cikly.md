# День 4 — Вложенные циклы, `break`, `continue`

> [!abstract] О чём эта лекция
> Нового синтаксиса почти нет — есть два новых слова и одна новая мысль. `break` и `continue` управляют ходом цикла изнутри тела. Вложенный цикл — цикл внутри цикла; на нём стоят таблицы, картинки в консоли и вся работа с двумерными данными. Зачёт дня — ромб из звёздочек, и он честно сложный.

---

## 1. Что добавляется к Дню 3

В Дне 3 цикл был устроен просто: условие проверяется сверху, тело выполняется целиком, шаг, снова проверка. Сегодня две добавки:

1. **Выйти или пропустить шаг посреди тела** — `break`, `continue`.
2. **Вложить цикл в цикл** — внутренний прокручивается полностью на каждом проходе внешнего.

Второе — единственная по-настоящему трудная идея дня. Первое запоминается за десять минут.

## 2. `break` — выйти из цикла немедленно

```cpp
for (int i = 1; i <= 10; i++) {
    if (i == 4) break;
    std::cout << i << " ";
}
// напечатает: 1 2 3
```

`break` прерывает цикл целиком. Шаг `i++` при этом **не выполняется**, условие **не проверяется**, управление уходит на первую строку после закрывающей `}` цикла.

| проход | `i` | `i == 4` | что делает |
|---|---|---|---|
| 1-й | 1 | ложь | печатает 1, шаг → `i` = 2 |
| 2-й | 2 | ложь | печатает 2, шаг → `i` = 3 |
| 3-й | 3 | ложь | печатает 3, шаг → `i` = 4 |
| 4-й | 4 | **истина** | `break` — выход, шага нет |

Зачем это нужно: как только ответ найден, продолжать бессмысленно. Вспомни задачу 19 из Дня 3 — простое ли число:

```cpp
bool prime = true;
for (int d = 2; d < n; d++) {
    if (n % d == 0) {
        prime = false;
        break;          // делитель найден, дальше искать нечего
    }
}
```

Без `break` программа доработает до конца и **даст тот же ответ** — просто сделает лишнюю работу. Для `n = 1000000` разница между двумя проходами и миллионом.

> [!important] `break` и `switch`
> В `switch` (День 2) `break` — это тот же самый оператор. Отсюда ловушка: `break`, стоящий внутри `switch`, который лежит внутри цикла, выйдет **из `switch`**, а не из цикла. Цикл спокойно продолжится. Именно на этом ломаются меню: пункт «выход» есть, а программа не закрывается.

## 3. `continue` — закончить текущий проход

```cpp
for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) continue;
    std::cout << i << " ";
}
// напечатает: 1 2 4 5 7 8 10
```

`continue` не выходит из цикла. Он говорит: «на этом проходе больше делать нечего, начинай следующий». Остаток тела пропускается, шаг `i++` выполняется, условие проверяется.

| | что делает | шаг `for` выполняется | условие проверяется |
|---|---|---|---|
| `break` | выходит из цикла насовсем | нет | нет |
| `continue` | заканчивает один проход | **да** | да |

> [!warning] Главная ловушка `continue` — в `while`
> ```cpp
> int i = 1;
> while (i <= 10) {
>     if (i % 3 == 0) continue;      // ЗАВИСАНИЕ
>     std::cout << i << " ";
>     i++;
> }
> ```
> В `while` нет отдельного шага — увеличение `i` написано последней строкой тела. `continue` перепрыгивает его. При `i == 3` управление уходит на проверку, `i` всё ещё 3, снова `continue`, и так навсегда. Программа висит молча, без вывода.
> **Лечение:** либо шаг стоит до `continue`, либо бери `for`, где шаг вынесен в заголовок и пропустить его невозможно.

Зачем `continue` вообще, если то же самое пишется через `if`? Ради читаемости. Когда в начале тела три проверки «этот случай нам не подходит», три `continue` подряд читаются легче, чем тело, завёрнутое в три вложенных `if`. Приём называется ранний выход, и дальше ты будешь видеть его постоянно.

## 4. `while (true)` — бесконечный цикл как рабочий инструмент

В Дне 3 бесконечный цикл был симптомом ошибки. Сегодня это законный приём: он нужен, когда условие выхода нельзя проверить в начале тела, потому что до выхода надо сначала что-то спросить или посчитать.

```cpp
while (true) {
    // ...
    if (пора выходить) break;
    // ...
}
```

`while (true)` и `for (;;)` — одно и то же. Условие всегда истинно, значит единственный выход — `break`.

> [!important] Правило
> Написал `while (true)` — в ту же минуту, не откладывая, пиши строку с `break`. Отложишь «на потом» — гарантированно получишь зависание и Ctrl+C.

### Скелет меню (задача 1)

```cpp
#include <iostream>

int main() {
    while (true) {
        std::cout << "\n1 - сложить\n2 - вычесть\n0 - выход\nВыбор: ";
        int choice;
        std::cin >> choice;

        if (choice == 0) {              // выход из ЦИКЛА — отдельным if,
            std::cout << "Пока.\n";     // до switch
            break;
        }

        switch (choice) {
            case 1: /* ... */ break;    // а этот break — от switch
            case 2: /* ... */ break;
            default: std::cout << "Нет такого пункта.\n";
        }
    }
    return 0;
}
```

Два `break` в одном экране означают разное. Проверку на выход держи **до** `switch` — тогда путаницы не будет.

### Проверка ввода (задача 13)

```cpp
int x;
do {
    std::cout << "Введи число от 1 до 10: ";
    std::cin >> x;
} while (x < 1 || x > 10);
```

Здесь `do-while` по делу: спросить нужно хотя бы один раз, а пока не спросили — проверять `x` нечего, там мусор.

> [!warning] Почему это зависает, если ввести букву
> `std::cin >> x` при вводе `abc` не может превратить текст в число. Он **не забирает** его из буфера и переходит в состояние ошибки. Дальше каждое чтение проваливается мгновенно, `x` не меняется, цикл крутится и заливает экран приглашениями. Лечение:
> ```cpp
> if (std::cin.fail()) {
>     std::cin.clear();                 // снять флаг ошибки
>     std::cin.ignore(10000, '\n');     // выбросить мусор из буфера
>     continue;                         // спросить заново
> }
> ```
> Запомни симптом: **экран залило собственным приглашением ко вводу** — значит `cin` в состоянии ошибки. Это же понадобится в проекте Дня 7, где обработка неверного ввода стоит в требованиях.

## 5. Вложенные циклы: идея, которую надо уложить в голову

```cpp
for (int i = 1; i <= 3; i++) {              // внешний
    for (int j = 1; j <= 3; j++) {          // внутренний
        std::cout << i << j << " ";
    }
    std::cout << std::endl;
}
```

Вывод:

```
11 12 13
21 22 23
31 32 33
```

**Главная мысль:** для внешнего цикла никакого «второго цикла» не существует. Внутренний цикл — это просто его тело, одна инструкция, которую надо выполнить целиком. Значит на **каждый один** проход внешнего внутренний прокручивается **полностью, с начала до конца**.

| проход внешнего | `i` | что делает внутренний | напечатано |
|---|---|---|---|
| 1-й | 1 | `j`: 1 → 2 → 3, потом выход | `11 12 13` + перевод строки |
| 2-й | 2 | `j`: 1 → 2 → 3, потом выход | `21 22 23` + перевод строки |
| 3-й | 3 | `j`: 1 → 2 → 3, потом выход | `31 32 33` + перевод строки |
| 4-я проверка | 4 | условие внешнего ложно | выход |

### Сколько раз выполнится тело

Внешний N проходов, внутренний M проходов на каждый → тело внутреннего выполняется **N × M** раз. 3 × 3 = 9. 10 × 10 = 100. 1000 × 1000 = миллион, и программа начнёт заметно думать.

Это первое место, где ты физически чувствуешь стоимость алгоритма: добавил один вложенный цикл — умножил работу, а не прибавил. Позже это назовут $O(n^2)$.

### Счётчик внутреннего цикла сбрасывается — и это правильно

`int j = 1` в круглых скобках внутреннего `for` — это инициализация, и она выполняется **при каждом входе** в цикл, то есть на каждом проходе внешнего. Поэтому `j` каждый раз снова 1. Если бы не сбрасывался, второй проход не сделал бы ни одной итерации.

Отсюда важнейшее следствие: **границы внутреннего цикла могут зависеть от счётчика внешнего.**

```cpp
for (int j = 1; j <= i; j++)     // сколько проходов — решает i
```

На этой одной строчке стоят все треугольники, пирамиды и ромбы дня.

> [!warning] Не называй оба счётчика `i`
> ```cpp
> for (int i = 1; i <= 3; i++) {
>     for (int i = 1; i <= 3; i++) {    // компилируется молча!
>     }
> }
> ```
> Внутренний `i` **затеняет** внешний (shadowing): внутри виден только новый. Компилятор промолчит, `-Wshadow` предупредит, а ты потеряешь час на «внешний цикл не двигается». Стандарт: `i`, `j`, `k` снаружи внутрь. Для рисования лучше `row` и `col` — сразу видно, что где.

## 6. Рисование в консоли: правило «строка за строкой»

Консоль умеет одно: печатать слева направо, сверху вниз. Вернуться на строку выше и что-то дописать нельзя. Из этого физического ограничения вытекает вся логика рисования.

> [!important] Закон рисования
> **Внешний цикл — строки. Внутренний — символы внутри строки. Перевод строки — только во внешнем цикле, после внутреннего.**
> `endl` внутри внутреннего цикла → вертикальная полоска вместо квадрата. Это ошибка №1 сегодняшнего дня, её совершают все.

### Квадрат (задача 5)

```cpp
for (int row = 1; row <= n; row++) {
    for (int col = 1; col <= n; col++) {
        std::cout << "* ";
    }
    std::cout << std::endl;        // ВНЕ внутреннего цикла
}
```

### Прямоугольный треугольник (задача 6)

Меняется одно: сколько звёздочек в строке — зависит от номера строки.

```cpp
for (int row = 1; row <= n; row++) {
    for (int col = 1; col <= row; col++) {    // <= row, а не <= n
        std::cout << "*";
    }
    std::cout << std::endl;
}
```

> [!tip] Метод, который работает для любой фигуры
> Не пытайся угадать формулу в голове. Нарисуй нужную картинку на бумаге для `n = 4` и составь таблицу: строка → сколько пробелов → сколько звёздочек. Формула читается из столбцов сама. Это тот же приём, что таблица трассировки из Дня 3, только для вывода.

### Перевёрнутый треугольник (задача 7)

Два способа, и оба стоит написать:

- внешний цикл вниз: `for (int row = n; row >= 1; row--)`, внутренний `col <= row`;
- внешний цикл вверх, а количество считать выражением: `col <= n - row + 1`.

Второй способ выглядит сложнее, но именно он понадобится для ромба, где обе половины живут в одном проходе.

### Пирамида (задача 8) — появляются пробелы

```
   *
  ***
 *****
*******
```

Таблица для `n = 4`:

| строка `row` | пробелов | звёздочек |
|---|---|---|
| 1 | 3 | 1 |
| 2 | 2 | 3 |
| 3 | 1 | 5 |
| 4 | 0 | 7 |

Смотришь на столбцы: пробелов `n - row`, звёздочек `2 * row - 1`. Значит внутри внешнего цикла нужны **два внутренних цикла подряд**:

```cpp
for (int row = 1; row <= n; row++) {
    for (int s = 1; s <= n - row; s++)     std::cout << ' ';
    for (int st = 1; st <= 2 * row - 1; st++) std::cout << '*';
    std::cout << std::endl;
}
```

Они идут **последовательно**, а не вложены друг в друга. Классическая ошибка — вложить второй в первый; тогда звёздочки напечатаются столько раз, сколько было пробелов, и фигура расплывётся.

> [!note] Почему `2 * row - 1`
> Звёздочек всегда нечётное число, иначе у фигуры нет центрального столбца. Каждая следующая строка добавляет по одной звезде слева и справа: 1, 3, 5, 7. Проверяй формулу на первой и последней строке — если сходится на краях, почти наверняка верна и в середине.

### Ромб (задача 10) — зачёт дня

Разбирать не буду, это твоя работа. Дам ровно два наблюдения:

1. Ромб — это пирамида, к которой снизу приклеена перевёрнутая пирамида. Верхнюю половину ты уже написал в задаче 8.
2. Самая широкая, средняя строка печатается **один раз**. Если у ромба получился «пояс» из двух одинаковых строк — ты знаешь, где именно смотреть границы.

Порядок работы: нарисуй ромб для `n = 3` на бумаге (пять строк), составь таблицу «строка / пробелы / звёздочки» на все пять, отдельно найди закономерность для нижней половины. Формулу не угадывают — её вычитывают из таблицы.

### Шахматная доска (задача 15)

Подсказка одна: `(row + col) % 2`. У соседних клеток сумма индексов отличается на единицу, значит чётность чередуется и по горизонтали, и по вертикали — ровно то, что нужно. Это тот же `% 2` из Дня 2, только по двум координатам сразу.

## 7. Ровные столбцы: `std::setw` (задача 9)

Проблема таблицы умножения: числа разной ширины (`7`, `42`, `100`), и столбцы разъезжаются. Решение — манипулятор `setw` из `<iomanip>`:

```cpp
#include <iostream>
#include <iomanip>

int main() {
    for (int i = 1; i <= 10; i++) {
        for (int j = 1; j <= 10; j++) {
            std::cout << std::setw(4) << i * j;
        }
        std::cout << std::endl;
    }
    return 0;
}
```

`setw(4)` означает «следующее значение вывести в поле шириной 4, дополнив пробелами слева». Действует **только на одно следующее значение**, а не на всю строку — это регулярно удивляет. Поэтому он стоит внутри цикла, перед каждым числом.

## 8. Перебор с проверкой внутри: вложенный цикл — это задача Дня 3

Задачи 4, 11, 12 (простые, палиндромы, совершенные числа до N) выглядят новыми, а собираются из готового:

- **внешний** цикл перебирает кандидатов от 1 до N;
- **внутри** — целиком задача из Дня 3, которая проверяет одно число.

Ты уже писал «простое ли число» и «палиндром ли число». Теперь они становятся телом цикла. Так вообще строятся программы: не решают большое, а вкладывают уже решённое маленькое.

```cpp
for (int n = 2; n <= N; n++) {
    bool prime = true;
    for (int d = 2; d * d <= n; d++) {        // проверка ОДНОГО числа
        if (n % d == 0) { prime = false; break; }
    }
    if (prime) std::cout << n << " ";
}
```

> [!tip] Почему `d * d <= n`, а не `d < n`
> Делители ходят парами: если $n = a \cdot b$, то один из множителей не больше $\sqrt{n}$. Значит выше корня искать нечего — там не найдётся ничего нового. Пишут именно `d * d <= n`, а не `d <= sqrt(n)`: умножение целых быстрее и точнее, а `sqrt` возвращает `double` со всеми его проблемами сравнения (День 2). Для `N = 100000` выигрыш в скорости — в сотни раз.

> [!warning] Флаг объявляется внутри внешнего цикла
> `bool prime = true;` стоит **внутри** внешнего цикла: для каждого нового числа проверка начинается с чистого листа. Вынесешь наружу — первое же составное число испортит ответ для всех следующих.
> Сравни с накопителем `sum` из Дня 3, который объявлялся наоборот, снаружи. Разница в сроке жизни: накопитель копит через все проходы, флаг живёт ровно один проход. Спрашивай себя каждый раз: эта переменная про весь перебор или про одно число?

## 9. `break` из вложенных циклов — что реально происходит

```cpp
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (j == 2) break;          // выходит ТОЛЬКО из внутреннего
        std::cout << i << j << " ";
    }
}
// напечатает: 11 21 31
```

`break` и `continue` действуют на **ближайший окружающий цикл** и ни на какой другой. В C++ нет `break 2;`. Внешний цикл продолжает работать как ни в чём не бывало — что здесь и видно: три прохода внешнего состоялись.

Если надо выйти сразу из обоих:

**Способ 1 — флаг.** Рабочий вариант на сегодня:

```cpp
bool done = false;
for (int i = 1; i <= 3 && !done; i++) {      // условие выхода и во внешнем
    for (int j = 1; j <= 3; j++) {
        if (/* нашли */) { done = true; break; }
    }
}
```

**Способ 2 — вынести вложенные циклы в функцию и сделать `return`.** Самый чистый, но функции — вторая неделя. Вспомни этот абзац, когда до них дойдёшь.

**Способ 3 — `goto`.** В языке есть, работает, и выход из вложенных циклов — единственное его хоть чем-то оправданное применение. Всё равно не используй: на первой неделе он создаст больше проблем, чем решит.

## 10. Типичные ошибки — читай перед тем, как звать на помощь

| Код / ситуация | Что происходит | Симптом |
|---|---|---|
| `endl` внутри внутреннего цикла | перевод строки после каждого символа | вместо фигуры вертикальная полоска |
| `endl` забыт совсем | всё в один поток | одна длинная строка звёздочек |
| `continue` в `while` до шага | `i` не меняется | молчаливое зависание, Ctrl+C |
| `break` в `switch` внутри цикла | выходит из `switch`, не из цикла | меню не закрывается по «0» |
| `while (true)` без `break` | выхода нет | зависание |
| оба счётчика названы `i` | внутренний затеняет внешний | «внешний цикл не двигается» |
| `bool prime` вынесен до внешнего цикла | не сбрасывается | после первого составного все составные |
| внутренний цикл `<= n` вместо `<= row` | все строки одинаковой длины | квадрат вместо треугольника |
| циклы пробелов и звёздочек вложены, а не подряд | звёздочки печатаются кратно чаще | фигура расплывается вправо |
| ввели букву вместо числа | `cin` в состоянии ошибки | экран залило приглашением ко вводу |
| `setw` поставлен один раз до цикла | действует на одно значение | столбцы всё равно разъехались |

> [!tip] Отладка вложенных циклов
> Первой строкой в тело внутреннего цикла:
> ```cpp
> std::cout << "[row=" << row << " col=" << col << "]";
> ```
> И запускай на **маленьком** `n`: 3, максимум 4. На `n = 20` в выводе не разобраться, на `n = 3` ошибка видна глазами. Дальше просто считай: если итераций должно быть 9, а скобок напечатано 12 — ищи границы циклов, ошибка в них.

## 13. Итог одной страницей

- `break` выходит из цикла целиком: ни шага, ни проверки. `continue` заканчивает один проход, и шаг в `for` при этом выполняется.
- В `while` увеличение счётчика должно стоять **до** `continue`, иначе зависание.
- `while (true)` — законный приём, когда выход в середине тела. Написал `while (true)` — сразу пиши `break`.
- `break` внутри `switch` внутри цикла прерывает `switch`. Проверку на выход держи отдельным `if` до `switch`.
- Для внешнего цикла внутренний — просто тело. На один проход внешнего внутренний прокручивается целиком. Тело выполняется N × M раз.
- Счётчик внутреннего цикла сбрасывается при каждом входе. Поэтому его границы могут зависеть от счётчика внешнего — на этом стоят все фигуры дня.
- Рисование: внешний цикл — строки, внутренний — символы, `endl` только во внешнем.
- Формулу фигуры не угадывают: рисуешь на бумаге для `n = 4`, составляешь таблицу «строка / пробелы / звёздочки», формула читается из столбцов.
- Циклы пробелов и звёздочек идут **подряд**, а не вложенно.
- Флаг объявляется внутри того цикла, для одного прохода которого он живёт. Накопитель — снаружи.
- `break` действует только на ближайший цикл. Из двух сразу — флагом.
- Отладка: маленькое `n`, печать `row` и `col` в теле, счёт итераций.
